# EzCo

お手軽なコミックビューワーアプリケーション

**対応OS**: Windows（10/11推奨）

## 開発について

このプログラムの大半のコードはAI（Claude-4-Sonnet）によって実装されています。AIアシスタントとの協力により、効率的で高品質なソフトウェア開発を実現しています。

開発者向けの全体構造は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) です。画像読み込みは [docs/IMAGE_LOADING.md](docs/IMAGE_LOADING.md)、設計判断は [docs/DECISIONS.md](docs/DECISIONS.md)、開発時の注意は [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)、環境構築は [CONTRIBUTING.md](CONTRIBUTING.md) です。

## 機能

### 基本機能
- 画像ファイル（PNG, JPG, GIF, BMP, TIFF, WebP）の表示
- アーカイブファイル（ZIP, 7Z, RAR, CBZ, CBR, TAR, TAR.GZ, TAR.BZ2, TAR.XZ, GZ, BZ2, XZ, PDF）のサポート
- マウスジェスチャー操作
- ブックマーク機能
- 履歴機能
- 画像移動・ズーム機能
- ウィンドウ位置・サイズ・最大化の記憶（ファイルを開いていなくても終了時に保存）

### 多言語化対応
- **システム言語の自動検出**: アプリケーション起動時にシステムのデフォルト言語を自動検出
- **対応言語**: **日本語**（メイン）、**英語**（サブ）
- **言語切り替え**: langsフォルダに格納することで設定画面から言語を変更可能
- **言語ファイルの場所**: 
  - 実行フォルダの`langs`ディレクトリ（優先）
  - アプリケーション内蔵の`resources/langs`ディレクトリ

### デバッグ機能
- **デバッグモード**: 設定画面で有効化可能
- **ログファイル**: デバッグモード有効時、`logs`フォルダにタイムスタンプ付きログファイルを自動生成
- **詳細ログ**: ファイル処理、アーカイブ展開、画像読み込みなどの詳細な動作ログ
- **エラーログ**: エラー発生時の自動ログ記録

### タブ
- **複数ファイルを同時に表示**: タブバーはタブが 2 枚以上あるときだけ表示
- **タブメニュー**: 新規 / 閉じる / タブの再表示 / 左右・先頭・末尾へ移動。再表示できるタブが無いときはメニューを無効化
- **タブ一覧**: 機能／拡張 → サイドバーから開いているタブを一覧表示
- **フルスクリーン時のタブ**: 表示メニューのチェックで、フルスクリーン中もタブバーを出すか選べる
- **タブ切替**: 初回のショートカットは Ctrl+1〜9 で1〜9番目、Ctrl+0 と Ctrl+End で最後のタブ
- **タブバー**: 幅は固定。長い名前は省略し、マウスを乗せると全文を表示。中央クリックでそのタブを閉じる
- **メニュー**: ショートカット設定にあるキーボード割り当てを、項目の右側に表示
- **開く**: 「ファイルを開く」は今のタブ、「新しいタブでファイルを開く」は新規タブ、「フォルダを開く」はフォルダ選択
- **複数パス**: 画像はまとめて1タブのページ列。アーカイブ／フォルダを別タブにするかは設定で選べる（既定はアーカイブだけ別タブ）。タブの並びは選択／ドロップ順
- **ファイルダイアログ**: 先頭の「対応しているファイル」に画像・アーカイブ・プラグイン拡張子・状態ファイルをまとめて表示
- **状態の保存**: 「状態を名前をつけて保存」（初回は Ctrl+S）で全タブのファイルとページを `.ezs` に保存
- **状態の復元**: `.ezs` を開く／D&D。すでにファイルを開いているときは、すべて閉じる／開いているタブに追加／新規ウィンドウ／キャンセルを確認
- **D&D**: 設定の「既存のタブ / 新しいタブ」に従う。先頭グループのあと、別タブ指定のアーカイブ／フォルダなどは追加タブ
- **履歴・ブックマーク**: クリックは今のタブ、Ctrl+クリックまたは中央クリックは新規タブ。右クリックでも選べる
- **最後に開いたファイル**: タブ全部ではなく、履歴の最後の 1 件だけを開く

### プラグイン設定
- **導入確認**: プラグインがある初回（未同意）にはい／いいえ。はいならこのユーザーの同意バージョンを保存し、重複があればその次に選択。いいえならロードせず、メニューからプラグイン設定を出さない。次回も聞く。同意バージョンが上がったときも再表示
- **ON/OFF**: プラグイン単位で有効／無効。OFF にすると拡張子の担当から外れ、サイドバーも消える。OK / 適用で足り、再起動は不要
- **読み込み方式**: 拡張子ごとにビルドイン／プラグイン／読み込まないを選択。OK / 適用で開いているファイルを再読み込みする
- **id 重複**: 同意したあと、起動時にどれを読むか選ぶ。選んだ内容は保存され、新しい重複 id が出ない限り次回は聞かない。選び直すときはプラグイン設定の「重複プラグインの選択」（OK / 適用で反映。再起動は不要）
- **ライセンス**: ルートの `LICENSE.md` / `LICENSE.txt` / `LICENSE` を設定から読める（優先順はこの順。表示は保証ではない）
- **読み込まない**: 指定した拡張子のファイルを開かない（旧アーカイブ設定の代替）
- **設定のエクスポート/インポート**: 本体の設定ダイアログから、現在のプロファイルの設定をYAML形式で保存・復元

### コミック表示
- **単ページ / 両開き（右） / 両開き（左）**: メニューバーの「表示」から切り替え
- **両開き（右）**: 右が軸ページ N、左が N+1（右綴じ向け）
- **両開き（左）**: 左が軸ページ N、右が N+1（左綴じ向け）
- **見開き単位のページ送り**: 次/前は2ページずつ。最終奇数ページのみ単ページ
- **選択ページを軸**: スライダーで選んだページを見開きの先頭にする
- **スライダー方向**: 単ページ・両開き（右）は右が先頭。両開き（左）のみ左が先頭

### プロファイル
- **メニューから追加・管理・切替**: 「プロファイル」メニューで追加、改名・削除、選択
- **追加時は現在の設定をコピー**: 表示・ショートカット・プラグイン優先度など。履歴とブックマークはコピーせず空
- **設定はプロファイル単位**: 表示モード、背景色、言語、ショートカット、プラグイン選択などをプロファイルごとに保存
- **ブックマークと履歴も分離**: 各プロファイルで独立
- **既定プロファイルは削除不可**
- **CLI指定**: `--profile=名前` / `-p 名前` でそのセッションだけ使用（存在しない場合は前回のプロファイルを使用。新規作成はしない）

### UIフォント設定
- **フォントファミリ**: Windowsレジストリとfontフォルダから利用可能フォントを自動検出
- **フォントサイズ**: 8～64pxの範囲で設定可能
- **文字色・背景色**: カラーピッカーで自由に設定
- **透過度**: 0（透明）～255（不透明）で設定可能
- **ポップアップ表示**: ジェスチャー操作時のオーバーレイ表示に適用

### その他の機能
- **仮想パス機能**: アーカイブ内の特定ファイルを直接指定可能（`archive://path#filename`形式）
- **画像リスト表示**: 現在のファイル一覧をポップアップ表示
- **画像スライドサイドバー**: サムネイル表示によるページ一覧とクイック移動
- **ページスライダー**: 下部ドック（解除で浮き窓）。スライダーによるページナビゲーション
- **マウスロック機能**: マウスカーソルを画面中央に固定
- **画像回転機能**: 画像の90度回転
- **常に手前に表示**: ウィンドウを常に最前面に表示
- **最小スケール切り替え**: 画像の最小表示倍率を切り替え
- **ファイル名エンコーディング自動判定**: アーカイブ内の日本語ファイル名を自動デコード
- **画像プリフェッチ**: 高速なページめくりを実現
- **設定のエクスポート/インポート**: 現在のプロファイルの設定をYAML形式で保存・復元
- **状態ファイル**: 開いているタブを `.ezs` に保存し、開く／D&D で復元
- **プラグイン**: 実行ファイル旁 `plugins/` の ZIP または展開フォルダで独自形式の画像／アーカイブを読み込み可能

### プラグイン
- **配置**: 実行ファイル旁（開発時はリポジトリルート）の `plugins/` 直下に `.zip`、または `manifest.json` 付きフォルダを置く。新しい ZIP／フォルダの追加・削除だけ再起動が必要
- **注意**: 本体は中身を検査しない。置いたコードはアプリと同じ権限で動く。責任は配布者と導入した使用者。詳細は [plugins/README.md](plugins/README.md)
- **導入確認**: 未同意ならはい／いいえ。いいえならロードせず、プラグイン設定も出さない。次回も聞く。同意はユーザー単位。バージョンが上がったときも再表示
- **重複**: 同意したあと、同じ `id` が複数あるときは起動時にどれを読むか選ぶ。選ばれなかったものは設定一覧に理由付きで残る
- **設定**: メニューのプラグイン設定で、プラグインの ON/OFF と拡張子ごとの読み込み方式（ビルドイン／プラグイン／読み込まない）を選択。OK / 適用で開いているファイルを再読み込みする（再起動は不要）
- **ダイアログ**: 一覧の ID はバージョンなし。列の幅変更・並べ替えができ、レイアウトは保存される
- **既定**: ビルドインが知っている拡張子はビルドイン優先。プラグイン専用拡張子はそのプラグインが担当
- **ファイルダイアログ**: 有効なプラグインの拡張子は「対応しているファイル」と「プラグイン形式」に入る。フォルダを開いたときのスキャン対象にも含まれる
- **サンプル**: ソースは `plugins/`、配布 ZIP は [`dist-sample-plugins/`](dist-sample-plugins/)（PNG / ZIP / テキスト画像 / 商品情報サイドバー / 表示フィルター）
- **開発者向け**: [プラグインマニュアル](docs/plugins.md)、[本体の構造](docs/ARCHITECTURE.md)、ユーザーマニュアルの [プラグインリファレンス](resources/UserManual/files/plugin-reference.html)、各プラグインの `README.md`、[plugins/README.md](plugins/README.md)

### インストール

#### 自動セットアップ（推奨）

Cursor / VS Code の実行とデバッグ（`F5`）から **「▶ 初期化 (poetry run init-env)」** を選ぶか、タスク **「EzCo: 初期化」** を実行します。ターミナルから同じことをする場合：

```bash
poetry run init-env
```

`init-env` は以下を実行します：
- Poetry依存関係のインストール
- C++コンパイラの確認と設定
- MinGW-w64の自動ダウンロード（必要に応じて）
- セットアップの確認

#### 手動インストール

```bash
# 依存関係のインストール
poetry install

# 開発用依存関係のインストール（Nuitkaビルド用）
poetry install --with dev
```

**注意**: 手動インストールの場合、Nuitkaビルドに必要なC++コンパイラが別途必要です。

### 実行

#### コマンドラインから実行

```bash
# 開発モードで実行
poetry run python -m ez_co.main

# または
poetry run python src/ez_co/main.py
```

#### Cursor / VS Code での実行

1. プロジェクトを開く
2. `F5`キーを押すか、「実行とデバッグ」パネルから「Python: EzCo」を選択
3. アプリケーションが起動します

※ `launch.json` により、開発モードでのデバッグ実行が可能です

## ビルド

### Nuitkaを使用したビルド

このプロジェクトはWindowsでのみビルド・実行をサポートしています。

#### 自動ビルド（推奨）

Launch の **「▶ ビルド (poetry run build)」** / **「▶ ビルド (--safe-mode)」**、またはターミナル：

```bash
# 標準ビルド（最適化あり）
poetry run build

# セーフモードビルド（最適化なし）
poetry run build -- --safe-mode
```

#### ビルドの内容

`poetry run build` は以下を実行します：

##### 標準ビルド（最適化あり）
- **LTO（Link Time Optimization）**: 実行時パフォーマンスを向上
- **ソースコード優先**: バイトコードよりソースコードを優先使用
- **ファイルサイズ**: やや大きくなる可能性
- **ビルド時間**: 長い（5-15分程度）

##### セーフモードビルド（最適化なし）
- **基本ビルド**: 最適化オプションなし
- **安全性重視**: 互換性問題を回避
- **ファイルサイズ**: やや小さい
- **ビルド時間**: 短い（3-10分程度）

#### ビルド前の準備

ビルドを実行する前に、以下を確認してください：

```bash
# 初期化（初回のみ）
poetry run init-env
```

#### 手動ビルド

通常は不要です。Nuitka を直接叩く場合の例は `tooling/build_cli.py` を見てください。

#### ビルド出力

- **実行ファイル**: `EzCo.exe`（プロジェクトルートに作成）
- **一時ファイル**: `build/`フォルダ（ビルド完了後に自動削除）

#### トラブルシューティング

##### ビルドエラーが発生する場合
1. **初期化の実行**: `poetry run init-env` でセットアップを確認
2. **セーフモード**: `poetry run build -- --safe-mode` を試行
3. **依存関係**: `poetry install --with dev` で依存関係を再インストール

##### コンパイラエラーが発生する場合
1. **Microsoft Visual Studio Build Tools**（推奨）
   - [公式サイト](https://aka.ms/buildtools)からダウンロード
   - 「C++ build tools」を選択してインストール
2. **MinGW-w64**（軽量オプション）
   - `poetry run init-env` で自動インストール可能
   - 手動インストールも可能

##### メモリ不足エラーの場合
- **8GB以上のRAM**を推奨
- **セーフモード**でビルドを試行
- **他のアプリケーション**を終了してメモリを確保

#### ビルド時間の目安

- **低スペックPC**: 10-20分
- **標準PC**: 5-15分
- **高スペックPC**: 3-10分

※ 初回ビルド時は追加のコンポーネントダウンロードにより時間がかかる場合があります

#### クイックスタートガイド

初めてプロジェクトをセットアップする場合の推奨手順：

```bash
# 1. 初期化（依存関係とコンパイラのセットアップ）
poetry run init-env

# 2. ビルド実行
poetry run build

# 3. アプリケーション実行
./EzCo.exe
```

#### 開発とビルドのワークフロー

```bash
# 開発時の実行
poetry run python -m ez_co.main

# ビルド前の動作確認
poetry run python src/ez_co/main.py

# リリースビルド
poetry run build

# 問題が発生した場合のセーフビルド
poetry run build -- --safe-mode
```

## 設定

アプリケーションの設定は`config.db`（SQLite）に、プロファイル単位で保存されます。初回起動時に自動作成されます。旧バージョンの`bookmarks.db`だけがある場合は`config.db`へリネームされます。残っている`config.yaml`は起動時の確認ダイアログで取り込みできます。

### 主な設定項目

#### ウィンドウ設定
- **サイズ・位置**: ウィンドウのサイズと位置を記憶（設定で有効にしたとき）
- **サイドバー**: 開いていたサイドバー、左右の位置、幅をプロファイル単位で保存し、次回起動時とプロファイル切替時に復元
- **自動リサイズ**: 画像読み込み時のウィンドウサイズ自動調整
- **最小サイズ**: ウィンドウの最小幅・高さ
- **常に手前に表示**: ウィンドウを常に最前面に表示

#### ビューア設定
- **背景色**: 画像表示エリアの背景色
- **画像をウィンドウに合わせる**: 画像をウィンドウサイズに自動調整
- **最小縮小率制限**: 画像の最小縮小率を100%までに制限
- **画像移動感度**: マウスドラッグ時の画像移動感度（0.5～2.0）
- **ページ表示モード**: 単ページ / 両開き（右） / 両開き（左）
- **選択ページを軸**: スライダーで選んだページを見開きの先頭にする
- **両開き／単ページ切替の優先**: 前回の選択を維持 / 右を優先 / 左を優先

#### 履歴設定
- **最大履歴数**: 履歴に保存するファイル数の上限（1-99）

#### デバッグ設定
- **デバッグモード**: 詳細ログの出力有効/無効
- **ログファイル**: `logs`フォルダにタイムスタンプ付きログファイルを生成
- **アーカイブファイルハンドルを保持**: アーカイブファイルハンドルの保持設定（通常は無効推奨）

#### キャッシュ設定
- **メモリキャッシュサイズ**: 画像のメモリキャッシュサイズ（例：256MB、1GB、2.5GB）
- **プリフェッチページ数**: 現在のページから前後何ページ分を先読みキャッシュするか（1-50ページ）

#### プラグイン設定
- **ON/OFF**: `plugins.enabled`。未記載は有効。OFF にするとサイドバーも消える
- **読み込み方式**: 拡張子ごとにビルドイン／プラグイン／読み込まない
- **読み込まない**: その拡張子のファイルを開かない（アーカイブ・画像の両方）

#### 言語設定
- **言語コード**: 使用言語の設定（system、ja、en）
- **システムデフォルト**: システムのデフォルト言語を使用

#### UIフォント設定
- **フォントファミリ**: ポップアップ表示用のフォント
- **フォントサイズ**: フォントサイズ（8-64px）
- **文字色**: ポップアップの文字色
- **背景色**: ポップアップの背景色
- **透過度**: ポップアップの透過度（0-255）

#### ショートカット設定
- **キーボードショートカット**: 各アクションのキーボード割り当て
- **マウスショートカット**: マウス操作の割り当て

#### ジェスチャー設定
- **マウスジェスチャー**: マウスドラッグによるジェスチャー操作の割り当て

## プラグイン設定について

### 概要
EzCoでは、拡張子ごとの読み込み方式を選べます。特定の形式が不要な場合や、読み込み速度を上げたい場合は「読み込まない」を指定します。旧アーカイブ設定ダイアログの代替です。

### 設定方法
1. アプリケーションを起動
2. 設定 → プラグイン設定
3. プラグインの有効チェックと、拡張子ごとの「ビルドイン」「プラグイン」「読み込まない」を選ぶ
4. OK で保存する（開いているファイルは再読み込みされる。無効にしたサイドバーは消える）

### 設定の効果

#### 読み込まないを選んだ場合
- その拡張子のファイルは開かれません
- フォルダを開いた際もスキップされます
- 画像・アーカイブの両方に使えます

#### アーカイブだけを開きたくない場合
- ZIP、7Z、RAR など、対象のアーカイブ拡張子を「読み込まない」にする
- 画像ファイルのみが表示されます

### 使用例

#### 例1: 7Zファイルを開かない
- 7Zが大量にあるフォルダで読み込みが遅い場合
- プラグイン設定で `.7z` の読み込み方式を「読み込まない」にする

#### 例2: 圧縮ファイルをすべて開かない
- 画像ファイルのみを表示したい場合
- `.zip`、`.7z`、`.rar`、`.tar`、`.gz` などを「読み込まない」にする

#### 例3: コミックファイルだけ開く
- CBZとCBRだけ使う場合
- 他のアーカイブ拡張子を「読み込まない」にする

### 設定のエクスポート/インポート
- 本体の設定ダイアログからエクスポート／インポートする
- YAML形式で現在のプロファイルを保存・復元する

### 注意事項
- OK / 適用すると開いているファイルは再読み込みされます（再起動は不要）
- 「読み込まない」にしたファイルはフォルダスキャン時にスキップされます
- 旧プロファイルのアーカイブ無効設定は、プラグイン設定を開いたときに「読み込まない」として表示されます

### 対応アーカイブ形式
- **ZIP**: .zip
- **7-Zip**: .7z
- **RAR**: .rar
- **TAR**: .tar
- **TAR.GZ**: .tar.gz, .tgz
- **TAR.BZ2**: .tar.bz2, .tbz2
- **TAR.XZ**: .tar.xz, .txz
- **GZ**: .gz
- **BZ2**: .bz2
- **XZ**: .xz
- **CBZ**: .cbz（ZIPベースのコミック）
- **CBR**: .cbr（RARベースのコミック）
- **PDF**: .pdf（ページをそのまま表示。描画できない場合は埋め込み画像）

## プラグインについて

実行ファイルと同じ階層の `plugins/` に ZIP、または `manifest.json` 付きフォルダを置くと、本体に無い形式や、既存拡張子の代替読み込みを追加できます。プラグインは画像バイトを返すだけで、描画は本体が行います。

本体はプラグインの中身を検査しません。置いたコードはアプリと同じ権限で動きます。悪意のあるコードや欠陥による損害について、EzCo の開発者は責任を負いません。詳細は [plugins/README.md](plugins/README.md) です。

### 使い方
- ZIP または展開フォルダを `plugins/` **直下**に置く（入れ子は読まれない）
- 未同意なら起動時にはい／いいえ。いいえならロードせず、プラグイン設定も出さない。次回も聞く。同意はユーザー単位。バージョンが上がったときも再表示。はいのあと、同じ `id` が複数あるときは1つ選ぶ（または読み込まない）。選んだ内容は保存され、新しい重複 id が出ない限り次回は聞かない。選び直すときはプラグイン設定の「重複プラグインの選択」（OK / 適用で反映。再起動は不要）
- ルートに `LICENSE.md` / `LICENSE.txt` / `LICENSE` があれば、プラグイン設定の「ライセンス」から読める（優先順はこの順。表示は保証ではない）
- 新しい ZIP／フォルダを置いた（または消した）あとだけアプリを再起動する。起動中に足しただけでは一覧に出ない
- 「プラグイン設定」でプラグインの ON/OFF と拡張子ごとの読み込み方式を選ぶ（ビルドイン／プラグイン／読み込まない）。OK / 適用で開いているファイルを再読み込みする（ページ数が減った場合は末尾に寄せる）。再起動は不要
- 一覧の列はドラッグで幅変更・並べ替えできる。幅と列順は保存される（キャンセルしてもレイアウトは残る）

### 開発
- 契約・メソッド・ホスト API の詳細は [docs/plugins.md](docs/plugins.md)
- 配置・注意・再起動の区別は [plugins/README.md](plugins/README.md)
- プラグインから `ez_co` は import できない（結合事故防止であり、サンドボックスではない）。ホストは `Class()` のあと `load(root, get_text, host)` を渡す。ダイアログは `host.ask_password` など
- ZIP の AES 暗号化は本体・サンプルとも `pyzipper` で読む

## キャッシュ設定について

### 概要
EzCoでは、画像の読み込み速度を向上させるために、メモリキャッシュとプリフェッチ機能を提供しています。これらの設定により、ページめくりの応答性を大幅に改善できます。

### 設定方法
1. アプリケーションを起動
2. 設定画面を開く
3. 「動作」タブを選択
4. 「キャッシュ設定」セクションで各項目を設定
5. 設定を保存

### このPCに合わせて決める
キャッシュ設定には2つのボタンがあります。どちらも入力欄の値を変えるだけで、「適用」または「OK」を押すまで保存されません。

- **PCに合わせた推奨設定に戻す**: このPCのCPUと搭載メモリから決めた推奨値を入れます
- **このPCで最適な設定を測定...**: 実際に画像を読み込んで組み合わせを比べます。数十秒から数分かかり、その間はEzCoを操作できません

初回起動時など設定を新しく作るときは、測定せずに推奨値が初期値として入ります。起動オプションで画像読み込み設定を固定している場合、測定ボタンは使えません。

### メモリキャッシュサイズ

#### 概要
読み込んだ画像をメモリに保持するキャッシュのサイズを設定します。大きくしても必ず速くなるわけではありません。先読みが届く範囲を超えた分は、使用メモリだけが増えます。

#### 設定値
- **フォーマット**: 文字列形式（例：256MB、1GB、2.5GB）
- **デフォルト**: 256MB（搭載メモリ16GB以上のPCで新しく設定を作ると512MB）

#### 設定例
- **高解像度の本を複数タブで開く**: 512MB以上
- **それ以外**: 既定のままで十分
- **迷うとき**: 設定画面の「このPCで最適な設定を測定...」で確かめられます

#### 注意事項
- 設定値が大きすぎると、システムメモリが不足する可能性があります
- 他のアプリケーションで使用するメモリを考慮して設定してください
- 設定変更は即座に反映されます

### プリフェッチページ数

#### 概要
現在のページから前後何ページ分を先読みしてキャッシュするかを設定します。大きくしても必ず速くなるわけではありません。読み進む前に追い出される先読みが増えると、同じページを読み直すことになり、かえって遅くなります。

#### 設定値
- **範囲**: 1～50ページ
- **デフォルト**: 5ページ

#### 動作例
- **設定値5**: 現在のページから前後5ページ（合計11ページ）を先読み
- **現在が10ページの場合**: 5～15ページをキャッシュ対象とする

#### 最適化のポイント
- **基本**: 既定の5前後。通常の画像でも高解像度でも5が最も安定していました
- **ページを飛ばして読むことが多い**: 10程度まで
- **増やすとき**: メモリキャッシュサイズも一緒に増やしてください

### キャッシュの動作仕様

#### 距離ベース削除
メモリキャッシュが上限に達した場合、現在のページから最も遠いページの画像から削除されます。これにより、現在閲覧中のページ周辺の画像が優先的に保持されます。

#### プリフェッチの優先度
1. **現在のページ**: 最優先
2. **次のページ**: 高優先度
3. **前のページ**: 高優先度
4. **前後2～3ページ**: 中優先度
5. **それ以降**: 低優先度

#### バックグラウンド処理
プリフェッチは別スレッドで実行されるため、メインの画像表示には影響しません。ただし、ファイルハンドル非保持モード時は、一部のアーカイブでプリフェッチが制限される場合があります。

### パフォーマンスへの影響

#### 推奨設定（標準環境）
```yaml
cache:
  memory_limit: "512MB"
  prefetch_pages: 5
```

#### ページを飛ばして読むとき
```yaml
cache:
  memory_limit: "1GB"
  prefetch_pages: 10
```

#### 省メモリ設定
```yaml
cache:
  memory_limit: "128MB"
  prefetch_pages: 5
```

## ファイルハンドル管理について

### 概要
EzCoでは、アーカイブファイルやフォルダを開く際のファイルハンドル管理方法を選択できます。この設定により、ファイルロックの発生を制御し、フォルダやファイルの移動・削除を可能にできます。

### ファイルハンドル保持モード

#### 通常モード（アーカイブファイルハンドルを保持: **無効**）【推奨】
- **動作**: ファイルアクセス時に都度開閉
- **メリット**: 
  - ファイルロックが発生しない
  - フォルダやファイルの移動・削除が可能
  - 他のアプリケーションからファイルアクセス可能
- **デメリット**: 
  - 大きなアーカイブファイルで読み込み速度がわずかに低下する可能性
  - ネットワークドライブでのアクセス時に遅延の可能性

#### ファイルハンドル保持モード（アーカイブファイルハンドルを保持: **有効**）
- **動作**: ファイルハンドルを常時保持
- **メリット**: 
  - 高速なファイルアクセス
  - ネットワークドライブでのパフォーマンス向上
- **デメリット**: 
  - ⚠️ **ファイルロックが発生**
  - フォルダやファイルの移動・削除ができない
  - 他のアプリケーションからファイルアクセス不可

### 設定方法
1. アプリケーションを起動
2. 設定画面を開く
3. 「開発」タブを選択
4. 「デバッグ設定」セクションで「アーカイブファイルハンドルを保持」のチェック状態を変更
5. 設定を保存

### 推奨設定

#### 一般的な使用（推奨）
```yaml
debug:
  keep_archive_handles: false
```
- ファイルロックを回避
- フォルダ・ファイルの自由な操作が可能

#### 高速化重視の場合
```yaml
debug:
  keep_archive_handles: true
```
- 最高速度でのファイルアクセス
- ただし、ファイルロックが発生することを理解した上で使用

### 対象ファイル形式
この設定は以下のファイル形式に適用されます：
- **ZIP**: .zip、.cbz
- **TAR**: .tar、.tar.gz、.tar.bz2、.tar.xz
- **圧縮ファイル**: .gz、.bz2、.xz
- **フォルダスキャン**: ディレクトリ内のファイル検索

### 影響を受けない形式
以下の形式は常に適切なハンドル管理が行われます：
- **7Z**: .7z（専用ライブラリのため）
- **RAR**: .rar、.cbr（専用ライブラリのため）

### 使用例

#### 例1: コミック整理作業中
- 設定: `keep_archive_handles: false`
- 理由: ファイルの移動・リネーム・削除を頻繁に行うため

#### 例2: 読書専用環境
- 設定: `keep_archive_handles: true`
- 理由: ファイル操作は行わず、読み込み速度を最優先

#### 例3: ネットワークドライブ使用
- 設定: `keep_archive_handles: true`
- 理由: ネットワーク遅延を最小化

### トラブルシューティング

#### ファイルが削除・移動できない
1. 設定で「アーカイブファイルハンドルを保持」が有効になっていないか確認
2. 無効にして設定を保存
3. アプリケーションを再起動（必要に応じて）

#### 読み込み速度が遅い
1. 設定で「アーカイブファイルハンドルを保持」を有効にする
2. キャッシュ設定でメモリキャッシュサイズを増加
3. プリフェッチページ数を調整

#### 他のアプリケーションからファイルにアクセスできない
1. 設定で「アーカイブファイルハンドルを保持」を無効にする
2. EzCoでファイルを閉じる
3. 他のアプリケーションからアクセスを試行

## 仮想パス機能について

### 概要
EzCoでは、アーカイブファイル内の特定の画像ファイルを直接指定して開くことができます。この機能により、大きなアーカイブファイルから特定の画像を素早く表示できます。

### 仮想パスの形式
```
archive://アーカイブファイルのパス|アーカイブ内のファイル名
```

### 使用例
- `archive://C:\comics\manga.zip|page001.jpg` - ZIPファイル内の特定画像
- `archive://D:\books\comic.cbr|chapter1/001.png` - CBRファイル内のフォルダ内画像
- `archive:///home/user/comics/story.7z|cover.jpg` - 7Zファイル内の表紙画像
- `archive://C:\books\magazine.pdf|page_0001.png` - PDFの1ページ目

### 対応アーカイブ形式
- ZIP、7Z、RAR、CBZ、CBR、TAR、TAR.GZ、TAR.BZ2、TAR.XZ、GZ、BZ2、XZ、PDF

### 使用方法
1. **コマンドライン引数**: アプリケーション起動時に仮想パスを指定
2. **ファイル関連付け**: 仮想パスを含むファイルをダブルクリック
3. **ドラッグ&ドロップ**: 仮想パスを記述したテキストファイルをドラッグ

### 注意事項
- アーカイブファイルが存在しない場合はエラーになります
- アーカイブ内のファイル名は正確に指定する必要があります
- 文字エンコーディングの問題で一部のファイル名が認識されない場合があります

## ショートカット設定について

### 概要
EzCoでは、キーボードとマウスの両方でショートカットを設定できます。各アクションに対して複数のショートカットを割り当てることができ、設定のエクスポート/インポートも可能です。

### 設定方法
1. 設定画面から「ショートカット設定」を選択
2. 「追加」ボタンで新しいショートカットを追加
3. 「編集」ボタンで既存のショートカットを変更
4. 「削除」ボタンでショートカットを削除

### キーボードショートカット
- **修飾キー**: Ctrl、Alt、Shift、Meta（Windowsキー）
- **特殊キー**: F1-F12、方向キー、Home、End、PageUp、PageDown、Space、Enter、Escape、Tab、Backspace、Delete
- **組み合わせ**: `Ctrl+Shift+A`、`Alt+F4`など

### マウスショートカット
- **マウスボタン**: 左クリック、右クリック、中クリック、X1ボタン（戻る）、X2ボタン（進む）
- **ホイール操作**: ホイールアップ、ホイールダウン
- **ダブルクリック**: ダブルクリック

### デフォルトショートカット
- **ページ操作**: 左クリック/右クリック、方向キー、Space
- **ファイル操作**: Ctrl+方向キー（前後のファイル）
- **ズーム操作**: ホイール。Ctrl+0 は初期状態では最後のタブ切替が先に動く（ズームリセットも同じキー）
- **タブ操作**: Ctrl+T（新規）、Ctrl+W（閉じる）、Ctrl+Shift+T（再表示）、Ctrl+PageUp / PageDown（左右）、Ctrl+Home / End（先頭／末尾）、Ctrl+1〜9（1〜9番目）、Ctrl+0（最後）
- **表示操作**: Return（フルスクリーン）、Ctrl+T（常に手前。新規タブと同じ初期キー）
- **その他**: Ctrl+L（画像リスト）、R（最後のファイルを開く）、Ctrl+S（状態を名前をつけて保存）、Ctrl+Shift+O（新しいタブでファイルを開く）
- **初回のみ**: デフォルトのショートカット／ジェスチャーは、プロファイルが無い初回起動（または新規プロファイル作成）のときだけ入る。消した割り当ては再起動しても戻らない

### 設定のエクスポート/インポート
- **エクスポート**: 現在のプロファイルの設定をYAML形式で保存
- **インポート**: YAMLファイルから現在のプロファイルの設定を上書き復元
- **自動補完**: インポート時に不足項目を自動追加

## マウスジェスチャーについて

### 概要
EzCoでは、右クリックを押したままマウスをドラッグすることでジェスチャー操作が可能です。複雑な操作を素早く実行できます。

### ジェスチャーの基本
- **開始**: 右クリックを押す
- **描画**: マウスをドラッグして方向を指定
- **実行**: 右クリックを離す

### 方向の認識
- **↑**: 上方向へのドラッグ
- **↓**: 下方向へのドラッグ
- **←**: 左方向へのドラッグ
- **→**: 右方向へのドラッグ

### ジェスチャーの組み合わせ
- **単一方向**: ←（前のコミック）、→（次のコミック）、↓（終了）
- **複合方向**: ↓→（フルスクリーン）、↑↓（最後のファイルを開く）、→←（最初のページ）、←→（最後のページ）

### 設定方法
1. 設定画面から「ジェスチャー設定」を選択
2. 「追加」ボタンで新しいジェスチャーを登録
3. ジェスチャー描画エリアで右クリックドラッグ
4. 実行したいアクションを選択

### デフォルトジェスチャー（初回プロファイル作成時のみ）
- **←**: 前のコミック
- **→**: 次のコミック
- **↓**: アプリケーション終了
- **↓→**: フルスクリーン切り替え
- **↑↓**: 最後に開いたファイルを開く
- **→←**: 最初のページ
- **←→**: 最後のページ
- **↓→←**: ページスライダー

### ジェスチャーの表示
- **リアルタイム表示**: ドラッグ中に現在のジェスチャーを表示
- **アクション表示**: 割り当てられたアクション名を表示
- **未割当表示**: 割り当てられていないジェスチャーは「未割当」と表示

### 設定のエクスポート/インポート
- **エクスポート**: JSON形式でジェスチャー設定を保存
- **インポート**: JSONファイルからジェスチャー設定を復元
- **バリデーション**: 無効なアクションは自動的に除外

## 画像リスト機能について

### 概要
現在開いているファイルの一覧をポップアップ表示し、任意のページに素早くジャンプできます。

### 表示方法
- **ショートカット**: Ctrl+L（デフォルト）
- **メニュー**: 表示 → 画像リスト

### 表示内容
- **ファイル名**: アーカイブ内のファイル名
- **サムネイル**: 画像のプレビュー（対応形式のみ）
- **ページ番号**: 現在のページ位置

### 操作方法
- **クリック**: 選択したページにジャンプ
- **キーボード**: 方向キーで選択、Enterで決定
- **検索**: ファイル名での検索（一部対応）

### 表示オプション
- **サムネイルサイズ**: プレビュー画像のサイズ調整
- **表示件数**: 一度に表示するファイル数
- **ソート順**: ファイル名順、日付順など

## 画像スライドサイドバー機能について

### 概要
画像スライドサイドバーは、現在開いているファイルのサムネイル一覧をサイドバーに表示し、任意のページへの素早い移動を可能にする機能です。

### 表示方法
- **メニュー**: 表示 → 画像スライド
- **ショートカット**: 設定可能（デフォルトなし）

### 機能
- **サムネイル表示**: 各ページのプレビュー画像を自動生成
- **リアルタイム更新**: ファイル変更時の自動リロード
- **現在ページのハイライト**: 現在表示中のページを視覚的に強調
- **クリック移動**: サムネイルクリックで該当ページに即座に移動
- **自動スクロール**: 現在ページが見えるように自動的にスクロール調整

### サイドバーの特徴
- **ドッキング可能**: 左右のエリアにドッキング表示
- **サイズ調整**: 横幅200-350px（固定）
- **表示/非表示切り替え**: メニューまたはショートカットで簡単切り替え
- **バックグラウンド読み込み**: 別スレッドでサムネイル生成により動作軽快

### 対応ファイル
- **画像ファイル**: PNG、JPG、GIF、BMP、TIFF、WebP
- **アーカイブファイル**: ZIP、7Z、RAR、CBZ、CBR内の画像

## ページスライダー機能について

### 概要
ページスライダーは、スライダーによるページナビゲーションです。既定ではウィンドウ下部にドックします。

### 表示方法
- **ショートカット**: 設定可能（デフォルトなし）
- **メニュー**: 機能／拡張 → ページスライダー
- **フルスクリーン**: 表示 → フルスクリーン時にページスライダーを隠さない（既定では隠す）

### 機能
- **リアルタイムスライダー**: ページ番号をスライダーで直感的に選択
- **数値入力**: スピンボックスによる正確なページ番号指定
- **クイックジャンプ**: 最初/最後のページへのワンクリック移動
- **リアルタイム更新**: ファイル変更やページ移動の自動反映

### ドックと浮き窓
- **結合**: 上下のみ。1行（スライダー＋入力＋ボタン）。左右サイドバーがあるときは残り幅
- **解除**: 今までの浮き窓（情報ラベル、スライダー、ボタン）
- **常に最新**: 開いたまま現在のタブに追従
- **空のタブ**: 出したまま操作不可。閉じた本のページ情報は残さない

### 操作要素
- **ページ情報**: 現在ページ/総ページ数の表示（浮き窓）
- **ページスライダー**: ドラッグによるページ選択
- **ページ番号入力**: キーボードによる数値入力
- **最初ボタン**: 1ページ目へ移動
- **最後ボタン**: 最終ページへ移動
