⚙️ Settings

Settings are stored per profile in config.db (SQLite). Changes in the settings dialog apply to the current profile. YAML is used only for export and import. Access settings via Settings → Settings.

The data location (config.db, plugins, and similar files) is shared across profiles. You choose it on first launch, and you can change it later on the General tab. Changes apply the next time you start EzCo.

📂 Data location (all profiles)

The location setting is stored as user.json in this user's data folder. The UI does not show technical folder names.

  • This user's data folder (recommended) — data_location=user. Keeps config.db and plugins for this Windows user.
  • Same folder as the program — data_location=exe. Other users on this PC may be able to read or change those settings.
  • Choose a folder — data_location=custom. A shared folder can let other users read the settings.

💾 Cache Settings

Configure image caching and prefetching to improve page turning responsiveness.

Setting Description Default / Recommended
Memory cache size Size of memory cache for loaded images in string format (e.g., "256MB", "1GB", "2.5GB") Default: "256MB"
Recommended: "128MB"~"8GB"
Prefetch pages Number of pages to prefetch around current page (1-50) Default: 15
Recommended: 5-30

💡 Cache Operation

  • Distance-based Eviction: Removes images farthest from current page when memory limit is reached
  • Background Processing: Prefetching runs in separate threads without affecting main display
  • Optimization Tips: SSD environments: 10-15 pages; HDD environments: 20-30 pages

🐛 Debug & File Handle Settings

Configure debug features and file handle management for optimal performance.

Setting Description Default / Recommended
Debug mode Enable detailed logging to logs folder Disabled
Keep file/folder handles Control file handle management when opening archives and folders Disabled (Recommended)
Cache file metadata Cache archive structure information in memory for performance Enabled
Show error log when an error occurs Show a stack-trace dialog for plugin and unhandled host exceptions. The text can be copied. Disabled

⚠️ File Handle Management

  • Disabled (Recommended): No file locking, allows file/folder movement and deletion
  • Enabled: Faster file access but causes file locking, preventing file operations
  • Use Cases: Comic organization (disabled), reading-only (enabled), network drives (enabled)

🌐 Language Settings

EzCo supports multiple languages and automatic language detection.

🌐 Language Support

  • System Default: Automatically detects your system language
  • Built-in Languages: Japanese (ja) and English (en)
  • Custom Languages: Add custom language files to the langs folder
  • Language Priority: External language files override built-in ones
  • Plugin sidebars: Menus and sidebar titles update immediately. Text inside plugin sidebars stays the same until you restart.

  • Page Restoration: Remembers your reading progress and returns to the same page when reopening files
  • Startup Restoration: Continues where you left off when launching the application

🗂️ Tabs

Where files open depends on the command and the click.

  • File menu Open uses the current tab. Open in New Tab opens new tabs.
  • History and bookmarks: click = current tab, Ctrl+click or middle-click = new tab, or choose from the right-click menu.
  • Middle-click a tab to close it. Closing the last tab closes the window.
  • viewer.drop_opens_new_tab: false = drop into the current tab, true = drop into a new tab. After the first group, archives or folders set to own-tab open as extra tabs. Default: false
  • viewer.open_archives_in_own_tab: true = each archive is its own tab; false = include archives as pages with images. Kind follows Plugin Settings. Default: true
  • viewer.open_folders_in_own_tab: true = each folder is its own tab; false = include folders as pages with images. Default: false
  • viewer.show_tabs_in_fullscreen: View menu checkbox Don't Hide Tabs in Fullscreen. false hides the tab bar in fullscreen. The tab bar is also hidden when only one tab is open. Default: false
  • viewer.show_page_slider_in_fullscreen: View menu checkbox Don't Hide Page Slider in Fullscreen. false hides the page slider in fullscreen like other docks. true keeps it visible. The mouse is locked to the center in fullscreen, so the slider cannot be used. Default: false
  • Tab width is fixed. Long names are elided; hover shows the full name. Assigned keyboard shortcuts appear on the right of matching menu items

🔌 Plugin Settings

Use Plugin Settings to turn plugins on or off, choose a handler per extension, and inspect loaded plugins. Display filters are in the Filter menu and can be enabled separately from the plugin itself.

Put a ZIP or a folder with manifest.json directly under the data folder plugins/ (Settings → Data location).

Consent and restart

  • If plugins are present and you have not accepted, a Yes / No dialog appears at startup.
  • Yes writes the consent version to this user's user.json, then the duplicate-id dialog if needed.
  • No does not load plugins and hides this menu item. The question returns next start.
  • The dialog appears again if the host raises the consent version.
  • Restart after adding or removing a ZIP or folder.
  • On/off, handler choice, and changing a duplicate-id source apply on OK / Apply; no restart.

List and license

  • If more than one plugin has the same id, choose one after consent. Unselected plugins stay in the list with a reason.
  • A disabled plugin is treated as missing.
  • Root LICENSE.md / LICENSE.txt / LICENSE can be opened from the License column (that order; display is not a guarantee).
  • If a plugin registered fields, the Settings column opens its own values. Storage is explained in the Plugin Reference.

Notes

  • EzCo does not inspect plugin code. Placed code runs with the same privileges as the app.
  • The EzCo developers are not responsible for damage from malicious or defective plugins. Responsibility lies with the publisher and the person who installs it.
  • On/off and handlers are stored in the current profile.
  • Don't load replaces the old Archive Settings dialog.
  • Enabled plugin extensions appear in the file dialog under Supported Files and Plugin formats, and in folder scans.
  • The product info sidebar is the product_info plugin. Host APIs are in the Plugin Reference.
  • plugin_consent_version: string such as 1.0.0 in this user's user.json, not the profile. On Yes it copies src/ez_co/resources/plugin_consent/version.txt. Missing, invalid, or different from the file means not accepted. No does not write it. After changing the Markdown notice, raise version.txt. Plugins are not loaded and this menu item is hidden until you accept
  • plugins.enabled: plugin id → on/off. Missing ids are enabled. Off removes the plugin from extension handling and unmounts its sidebar
  • plugins.extension_handlers: extension → builtin, id(ver:version), or none (Don't load). OK / Apply reloads the open files (no restart). If the new page count is smaller, the last page is shown
  • plugins.source_choice: duplicate id → {source, seen}. source is the name under plugins/, or none. A resolved id is not asked again at startup while the chosen file still exists. New unresolved duplicate ids, or a missing chosen file, show the dialog again. Change the choice with Choose duplicate plugins in Plugin Settings; it applies on OK / Apply
  • plugins.dialog: column widths and order. Drag headers to resize or reorder; overflow scrolls horizontally. Layout is saved on OK and Cancel. The ID column does not include the version

👤 Profiles

Each profile has its own settings, bookmarks, and history. The current profile is stored in config.db as app_state.current_profile.

📋 Profile Concept

  • Independent Data: Settings, bookmarks, and history are isolated per profile
  • Purpose-based Organization: Separate work, personal, research, and other use cases
  • Menu Operations: Add, manage (rename/delete), and select from the Profile menu
  • New profiles copy current settings: Viewer, shortcuts, plugin handlers, and so on. Bookmarks and history stay empty
  • Default Cannot Be Deleted: The default profile created on first launch cannot be removed
Feature Description Usage
Profile Creation Create a new profile by copying the current settings (bookmarks and history stay empty) Profile menu → Add
Profile Switching Switch between existing profiles (applied immediately) Profile menu → select a name
Profile Management Rename or delete (settings, bookmarks, and history are removed) Profile menu → Manage
Startup Profile Use a profile for this session only if it already exists EzCo.exe --profile=ProfileName

📋 Menu

Use the Profile menu to add, manage, and select profiles. Add copies the current settings; bookmarks and history start empty.

🚀 Command Line

EzCo.exe --profile=ProfileName (or -p name) uses that profile for the session. If it does not exist, the last profile is used and nothing is created.

📥 Legacy YAML

A leftover config.yaml can be imported at startup after confirmation, into a chosen profile.

Profile Usage Examples

Purpose Profile Name Examples Description
Work "Work", "Business", "Office" Business-related documents and manuals
Personal "Personal", "Comics", "Entertainment" Personal images and manga reading
Research "Research", "Study", "Reference" Academic materials and technical documents
Project-based "Project A", "Client X" Specific project resource management

⚠️ Important Notes

  • Full Isolation: Display mode, background, language, shortcuts, plugin handlers, bookmarks, and history are per profile
  • Deletion Warning: Deleting a profile permanently removes its settings, bookmarks, and history
  • CLI Is Session-Only: --profile / -p does not change the last selected profile
  • Missing Names: A non-existent CLI profile is not created
  • Export/Import: YAML export and import overwrite the current profile

🎯 Profile Best Practices

  • Clear Purpose: Create profiles with clear, distinct purposes (work, personal, study)
  • Temporary Profiles: Create temporary profiles for specific tasks or projects
  • Batch Scripts: Use batch files to automate launching with specific profiles
  • Regular Cleanup: Periodically remove unused profiles to maintain organization
