🔌 プラグインリファレンス

本体がプラグインに渡す契約です。JavaDoc のように型と引数を並べています。ユーザー向けの配置手順は プラグイン設定 を、開発者向けの長文はリポジトリの docs/plugins.md を見てください。

API バージョン: 1　／　配置: データフォルダの plugins/ の ZIP、または manifest.json 付きフォルダ（設定の「データの置き場」）

提供物（どの形式を開くか、サイドバーを出すか、画像を書き換えられるか）は manifest.json が正です。host の登録 API は、そこに書いたものだけ通ります。

概要

プラグインはホストから生成され、コールバックされるだけです。入口は Class() のあと必須の load(root, get_text, host) です。ファイル読み込み・サイドバー・表示フィルターは別の役割で、1つのプラグインがいくつでも持てます。詳細は プラグインの種類 です。

  • import ez_co はできません（結合事故防止であり、サンドボックスではありません）。
  • 本体は中身を検査しません。置いたコードはアプリと同じ権限で動きます。
  • 悪意のあるコードや欠陥による損害について、EzCo の開発者は責任を負いません。責任は配布者と、それを導入した使用者にあります。
  • PySide6 と本体が入れているサードパーティは import できます。

プラグインの種類

種類はクラスを分ける必要はありません。同じ src/plugin.py の1クラスが、マニフェストに書いた役割を全部持てます。入口はどれも Class() と load(root, get_text, host) です。

役割マニフェストコード
ファイル読み込み formats（image は1枚、archive は中身をページに） get_file_count / list_entries / read_entry
サイドバー sidebar: true（widget や ID は書かない） setup() で register_sidebar または register_config_sidebar
表示フィルター permissions.filter: true setup() で register_filter。有効化はフィルターメニュー（プラグイン ON とは別）
設定項目 なし（スキーマはコードまたは JSON） load() で register_config / register_config_json
独自アクション なし register_action

formats も sidebar も無く、setup() も無いプラグインは読み込み失敗です。フィルターだけなら permissions.filter と setup() で足ります。

パッケージ構造

my_plugin.zip
├── manifest.json
├── src/                 # import ルート
│   └── plugin.py
├── resources/
│   └── langs/           # 新規の文言 ja.json / en.json
└── LICENSE.md           # 任意。設定のライセンス。.md → .txt → 無印
  • 余分な親フォルダを挟まないでください。新規向けの最小ツリーは resources/langs だけです。旧 langs/ と src/langs/ はまだ読みますが、選択肢としては載せません。
  • 同じ構成の展開フォルダを plugins/ 直下に置けば、ZIP にしなくても読み込まれます。
  • 未同意なら起動時にはい／いいえの確認が出ます。
  • はいのあと、同じ id が複数あるときは1つ選びます。選んだ内容は保存され、新しい重複 id が出ない限り次回は聞きません。
  • 選び直すときはプラグイン設定の「重複プラグインの選択」です。選ばれなかったものは一覧に理由付きで残ります。
  • ルートの LICENSE.md / LICENSE.txt / LICENSE はライセンス列から読めます（優先順はこの順。表示は保証ではありません）。

manifest.json

ZIP またはフォルダの直下に置きます。ホストはこのファイルだけを見てプラグインを識別します。

id string 必須

プラグイン ID。同じ id は同時に1つだけロードします。設定の保存キーは id(ver:version) です。プラグイン設定の ID 列にはバージョンを付けません。

name string 必須

一覧に出す表示名です。

version string 必須

パッケージ版です。重複選択ダイアログでは新しい版を上に出します。上げると設定キーが変わり、以前の保存値は引き継ぎません。

api_version int 必須

ホスト契約の版です。現在は 1 だけが有効です。

entry string 必須

モジュール:クラス です。src/ を import ルートとして読みます。例: plugin:FileLoader は src/plugin.py の FileLoader。リポジトリのサンプルと新規プラグインの入口は src/plugin.py に揃えます。

description string 任意

プラグイン設定に出す短い説明です。

author string 任意

作者名です。

permissions object 任意

本体がマニフェストから読む権限です。詳細は マニフェスト権限。プラグイン API では渡せません。

formats array 任意

担当する拡張子と種別。本体だけが読み、これが正です。[[".zip", "archive"]] または {ext, kind}。ext は string または配列。extension / type は読みません。image は1枚、archive は中身をページにします。

{
  "formats": [[[".txt", ".log"], "archive"]]
}
sidebar bool 任意

サイドバーを使う宣言です。widget や ID は書きません。実体は setup() の register_sidebar または register_config_sidebar です。マニフェストに無ければ読み込み失敗です。プラグイン設定の状態は「失敗: 権限がない登録がありました」になります。

{
  "sidebar": true
}

マニフェスト権限

manifest.json の permissions だけが正です。本体がロード前に読みます。register_sidebar や register_filter の引数では渡せません。OS のサンドボックスではありません。未知キーは無視します。値は JSON の true / false だけです（文字列 "false" や 1 は読み込み失敗）。

キーないとあると
filter register_filter は読み込み失敗。プラグイン設定の状態は「失敗: 権限がない登録がありました」 表示画像を加工するフィルターを台帳へ載せられる。登録しただけでは動かない。ユーザーがフィルターメニューで有効化した ID だけが pipe に入る
inactive_callback サイドバーを登録したプラグインは、ドックが全部非表示のとき current_changed を受け取らない 非表示でも current_changed が届く。拡張子だけのプラグインは書かない（もともと届く） 
{
  "permissions": {
    "filter": true,
    "inactive_callback": true
  }
}

FileLoader

ホストが manifest.entry のクラスを Class() で生成し、必須の load(root, get_text, host) のあと決まった名前のメソッドを呼びます。ez_co.plugins.api は import しません。サイドバーやフィルターだけのプラグインでも同じ入口です。担当形式は manifest.formats です。

画像ローダーの最小例（src/plugin.py）

class FileLoader:
    def __init__(self):
        self.root = None
        self.get_text = None
        self.host = None

    def load(self, root, get_text, host):
        self.root = root
        self.get_text = get_text
        self.host = host

    def get_file_count(self, file_path):
        return 1

    def list_entries(self, file_path):
        return [file_path.replace("\\", "/").split("/")[-1]]

    def read_entry(self, file_path, index):
        with open(file_path, "rb") as handle:
            data = handle.read()
        return _Entry(self.list_entries(file_path)[index], data)


class _Entry:
    def __init__(self, name, data):
        self.name = name
        self.data = data
ctorClass()

引数なし。クラス内で完結するフィールドだけを初期化します。root / get_text / host は受け取りません。register_* / on / off は例外になり読み込み失敗です。

def __init__(self):
    self.root = None
    self.get_text = None
    self.host = None
    self.widget = None
methodget_file_count(file_path: str) -> int

画像エントリ数。アーカイブなら len(list_entries(...))、画像なら通常 1。

def get_file_count(self, file_path):
    return len(self.list_entries(file_path))
methodlist_entries(file_path: str) -> sequence[str]

エントリ名の列。ディレクトリは返さない。返した順がページ順です。暗号化アーカイブはここでパスワードを取らないと件数 0 になります。

def list_entries(self, file_path):
    names = []
    with ZipFile(file_path) as archive:
        for name in archive.namelist():
            if name.endswith("/"):
                continue
            if name.lower().endswith((".png", ".jpg", ".webp")):
                names.append(name)
    return names
methodread_entry(file_path: str, index: int) -> object

name（str）と data（bytes、PIL が開ける画像）を持つオブジェクトを返します。ワーカーから呼ばれることがあります。同じプラグインの list_entries / read_entry は本体が直列化します。別スレッドから同じプラグインの読込へ再入し、その完了を同期的に待たないでください。UI はホスト API 経由。

def read_entry(self, file_path, index):
    name = self.list_entries(file_path)[index]
    with ZipFile(file_path) as archive:
        data = archive.read(name)
    return _Entry(name, data)
methodload(root, get_text, host)

必須。生成直後に1回、OFF でも呼びます。引数を self に保持します。register_config はここでよい。UI 系（register_sidebar / register_config_sidebar / required_setting_sidebar / register_action / register_filter / on / off）は例外になり読み込み失敗です。途中で例外なら本体がそのプラグインの台帳と設定スキーマを捨てます。

引数説明
rootプラグイン内ファイル。read_bytes / read_ui / read_asset / read_config / exists
get_text文言
host登録・設定・状態。メソッドは self.host.ask_password のように直接呼ぶ。getattr は使わない
 
def load(self, root, get_text, host):
    self.root = root
    self.get_text = get_text
    self.host = host
    host.register_config("strict", "bool", default=True, label="{strict}")
methodsetup() / teardown()

任意。有効化で setup、無効化で teardown のあと本体の clear_plugin がサイドバー・アクション・listener・そのプラグインのフィルター台帳を外します。pipe の ID は残します。設定スキーマは残ります。setup が例外なら teardown を試してから clear_plugin します。失敗理由は teardown に渡しません。off / unregister_* は無効化用に書かないでください。teardown は QThread や timer など所有物だけです。サイドバーなら先に manifest.sidebar: true。フィルターなら先に permissions.filter: true。setup は有効化のとき1回です。アプリ言語の変更では呼びません。

def setup(self):
    widget = self.host.load_ui(self.root.read_ui("sidebar.ui"))
    self.host.register_sidebar("info", "{title}", widget)
    self.host.on("current_changed", self._on_current)

def teardown(self):
    if self._thread is not None:
        self._thread.quit()
        self._thread.wait()
        self._thread = None
methodlanguage_changed()

任意。アプリの言語設定を変えたときだけ、ACTIVE なプラグインへ1回呼ばれます。引数なし。プラグイン内部ウィジェットの表示文言更新専用です。未実装なら何もしません。ここでは register_* / on / off は禁止です。例外はそのプラグインだけログし、ACTIVE のまま他プラグインとメニュー更新は続けます。OS の表示言語変更は自動では見ません。ドックの visible / area / floating / widget は維持し、タイトルを差し替えます。host が作った設定フォームは同じタイミングでラベルも差し替えます。required_setting_sidebar() を自前ウィジェットへ埋め込んだときは、ここから refresh_labels() を呼んでください。

host

コンストラクタ第 3 引数。同じ名前はモジュール組み込みにも渡ります。プラグインから bind は呼びません。登録 API はマニフェストの宣言と対です。メソッドは self.host.ask_password のように直接呼びます。getattr / hasattr / setattr で探さないでください。足りない API は host に足します。

methodhost.on(event, callback) / host.off(event, callback=None)

current_changed と config_changed。off で callback を省略するとそのイベントの自プラグイン分を全部外します。無効化の掃除は本体の clear_plugin です。off は有効中に外すときだけ。サイドバーを登録したプラグインへの current_changed は、ドックが表示中か permissions.inactive_callback があるときに限ります。config_changed は間引きません。

def _on_current(payload):
    self._refresh(payload.get("folder"))

def _on_config(payload):
    if payload.get("key") == "fetch_web":
        self._refresh(host.get_current("folder"))

host.on("current_changed", _on_current)
host.on("config_changed", _on_config)
host.off("current_changed")

methodhost.register_config_json(name) -> None

resources/config/ からの相対ファイル名です。load で明示して呼びます。自動では読みません。bytes / list は受け取りません。トップレベルはフィールド配列。キーは register_config と同じです。未知キーはエラーです。choices がクラス名、または enum / enum_type があるときはエラーです。Enum はコードの register_config だけです。表示文字列は {key} のまま台帳へ載せ、出す瞬間に展開します。途中失敗は load 例外になり、そのプラグインのスキーマごと消えます。

def load(self, root, get_text, host):
    self.host = host
    host.register_config_json("fields.json")
    host.register_config("style", "choice", Style.PLAIN, label="{style}", choices=Style)

methodhost.register_config_sidebar(sidebar_id, title, aliases=None) -> None

required_setting_sidebar() でフォームを作り、register_sidebar します。setup() のみ。先に manifest.sidebar: true と 1 件以上の config が必要です。config があるだけでは自動登録しません。生成サイドバーは全項目を即時保存します（数値は 500ms debounce。sync は見ません）。reload=True のキーを書いたあと host が reload_current() します。更新ボタンは無く、リセットは確認ダイアログ付きです。自前でページ位置を保って開き直すプラグインは reload を付けないでください。

def setup(self):
    self.host.register_config_sidebar("text_image", "{title}")

methodhost.register_filter(filter_id, title, process) -> None

プラグイン設定（コンフィグ）

本体の「プラグイン設定」ダイアログ（ON/OFF や拡張子の担当）と、各プラグインが持つ値は別物です。ここで扱うのは後者です。メソッドの型は register_config / get_config / set_config / delete_config を見てください。

スキーマ

  • load で host.register_config または host.register_config_json("fields.json") を呼びます。無効化してもスキーマは残るので、ここで登録してかまいません。__init__ では例外です。JSON のキーはコードと同じです。Enum は JSON から指定できません。
  • value_type は "bool" / "string" / "int" / "float" / "int_range" / "float_range" / "path" / "password" / "color" / "date" / "datetime" / "choice" / "font" / "charset" / "language" / "country" です。
  • int_range / float_range は範囲付きの単一値です。minimum / maximum / step は必須です。欠落・逆転・step <= 0 はエラーです。ダイアログはスライダーとスピンを並べ、項目名の末尾に範囲を付けます。float_range は step も付けます。
  • path は文字列。path_kind は "file"（省略時）または "directory"。path_filter はファイルダイアログのフィルタです。
  • password は画面ではマスクします。DB は Windows DPAPI。プラグインの get_config は平文です。
  • sync=True は設定ダイアログ専用です。数値（int / float / int_range / float_range）だけ効きます。最後の変更から 500ms 動かなくなってから保存し config_changed します。reload=True（ダイアログでは sync と併用）のとき現在画像を reload_current します。キャンセル（Esc / × 含む）はプレビュー値を、ダイアログを開いた時点（または最後の適用）へ戻します。reload 項目なら画像も戻します。生成サイドバーは sync を見ません。
  • color は #RRGGBB の文字列。date / datetime は UTC の Unix 秒（数値）。date はその日の 00:00:00 UTC です。
  • choice は choices（値の列、(value, label)、または Enum / member 列）が必要です。省略すると1行入力になります。Enum を渡したときだけ get_config / config_changed は member です。DB は canonical な .name です。既存設定を残すなら member 名を変えないでください。未知の name は default。複数で1件でも未知なら default 全体です。
  • charset / language / country は本体が一覧を持ちます。保存は codec 名 / 言語コード / 国コード。言語・国の表示は母語名で、アプリの UI 言語には合わせません。
  • multiple=True は JSON 配列です。[] は補完しません（0件を保存できます）。required=True（既定 False）は empty を保存しません。空 default は登録できます。空を表現できない型では required は実質追加制約になりません。
  • suffix は数値入力の右に出す表示だけで、保存値には付きません。description があるときだけホバーします（ラベルへのフォールバックはありません）。
  • label / description / suffix / choice の label は、文字列全体が {key} のときだけ表示時に訳します。"A{title}B" はそのままです。
  • 1つでも登録すると、プラグイン設定の一覧の設定列に「設定」ボタンが出ます。無い行は - です。

読み書き

  • get_config(key, default) は保存値を返します。未保存ならスキーマの default、それも無ければ引数の default です。型はスキーマに合わせて正規化します。Enum の choice は member、multiple=True は list です。
  • set_config(key, value) は型を揃えて保存し、そのプラグインだけへ config_changed（{key, value}）を送ります。required の empty は保存せず False です。他プラグインには来ません。
  • delete_config(key) は保存値だけ消します。スキーマは残るので、次の get_config は default に戻ります。
  • reset_config(key) は保存値を消してdefaultへ戻し、config_changed と設定変更後通知も送ります。
  • プラグイン API に plugin_id 引数はありません。渡された host は、そのプラグインの行だけを見ます。
  • host.get_app_config() は本体の language / viewer / cache / ui_font の読み取り専用です。プラグインの値ではありません。

保存場所

  • 現在のプロファイルの plugin_settings テーブルです。プロファイルを追加するとコピーされ、削除すると消えます。
  • 行の識別は plugin_id のハッシュです。他プラグインの行は読めません。
  • キーはプラグインが決めた短い名前（例 fetch_web）です。manifest.json の version を上げても、id が同じなら同じ行を読みます。
  • 拡張子の担当に使う id(ver:version) とは別です。あちらは本体の plugins.extension_handlers です。
  • YAML エクスポートには出ません。本体設定のエクスポート／インポートではコピーされません。
  • plugin_settings.value は JSON です。date / datetime / int / float / int_range / float_range は数値、color / path / charset / language / country は文字列です。Enum の choice も name 文字列です。multiple=True は配列です。password は DPAPI した文字列です。

設定ダイアログ

  • 一覧の「設定」を開くと、登録した項目だけの小さなダイアログが出ます。
  • そのダイアログの OK / 適用は、すぐ DB へ書きます。本体のプラグイン設定ダイアログの OK を待ちません。
  • 初期化は保存済みoverrideを削除してスキーマの default に戻します。非 sync は適用時、sync の数値はすぐresetします。required の空defaultも未設定状態として有効です。reload=True なら画像を開き直します。
  • キャンセルは、そのダイアログでまだ保存していない変更を捨てます。sync で先に書いたプレビューも、開いた時点（最後の適用）へ戻します。reload 項目なら画像も開き直します。Esc / × も同じです。
  • 値を変えたあとは config_changed を聞いて、サイドバーなどを更新してください。reload=True のソース開き直しはホストがやるので、重ねて reload_current しないでください。

設定サイドバー

  • register_config_sidebar は setup で明示したときだけフォームをドックへ載せます。config があるだけでは自動登録しません。
  • 全項目をすぐ set_config します。数値だけ 500ms debounce。choice / font / color / charset / bool は変更直後です。sync は見ません。required の空は保存しません（ウィジェットは保存値へ戻します）。
  • reload=True のキーを書いたあと host が reload_current() します（保存できたときだけ。リセット後は1回）。ページ位置を自前で保つプラグインは reload を付けず、config_changed から reload_current(page) してください。
  • 更新ボタンはありません。リセットは保存済みoverrideを削除してスキーマの default に戻します。required の空defaultも未設定状態として有効です。確認ダイアログのあとです。
  • フォームは他画面からの config_changed をウィジェットへ戻します。
def load(self, root, get_text, host):
    self.host = host
    host.register_config_json("fields.json")
    host.on("config_changed", self._on_config)

def _on_config(self, payload):
    if payload.get("key") == "fetch_web":
        self._apply(payload.get("value"))

# あとから読む
if host.get_config("fetch_web"):
    self._fetch(host.get_current("folder"))

イベント

current_changed

表示中のファイルが変わったとき。payload は {path, folder, page} です。サイドバーを登録したプラグインには、ドックが表示中か permissions.inactive_callback があるときだけ届きます。

config_changed

自プラグインの set_config のあと。payload は {key, value} です。他プラグインの変更は来ません。

def _on_current(payload):
    print(payload["folder"], payload["page"])

def _on_config(payload):
    print(payload["key"], payload["value"])

host.on("current_changed", _on_current)
host.on("config_changed", _on_config)

制約

  • import ez_co / 他プラグインの import は不可
  • ドックの貼り付け／フローティングは本体
  • 他プラグインの設定は読めない（plugin_id はハッシュ化）
  • DLL プラグインは未対応
  • 新しい ZIP／フォルダを置いた（または消した）あとは再起動が必要。ON/OFF、読み込み方式、重複の選び直しは OK / 適用で足りる
  • 未同意ならはい／いいえ。いいえならロードせず、プラグイン設定も出さない。同意はユーザー単位。バージョンが上がったときと次回起動でも聞く
  • 同じ id が複数あるときは、同意したあとの起動時に1つ選ぶ。選んだ内容は保存され、新しい重複 id が出ない限り次回は聞かない。選び直すときはプラグイン設定（OK / 適用。再起動は不要）
