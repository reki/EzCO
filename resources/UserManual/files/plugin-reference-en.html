🔌 Plugin Reference

Contract the host gives to plugins, listed like Javadoc. For end-user install steps see Plugin Settings. Longer developer notes live in docs/plugins.md.

API version: 1　／　Location: a ZIP or a folder with manifest.json in the data folder plugins/ (Settings → Data location)

What the plugin provides (formats, sidebar, rewriting the displayed image) is declared in manifest.json. Host register APIs only accept what the manifest already listed.

Overview

The host constructs the plugin and calls it. The entry is Class() then required load(root, get_text, host). File loading, sidebar, and display filters are separate roles; one plugin may take any combination. See Plugin roles.

  • import ez_co is not allowed (it prevents accidental coupling; it is not a sandbox).
  • EzCo does not inspect plugin code. Placed code runs with the same privileges as the app.
  • The EzCo developers are not responsible for damage from malicious or defective plugins. Responsibility lies with the publisher and the person who installs it.
  • PySide6 and host third-party packages are allowed.

Plugin roles

You do not need a separate class per role. One class in src/plugin.py can take every role the manifest declares. The entry is always Class() then load(root, get_text, host).

RoleManifestCode
File loading formats (image is one page; archive lists inner images) get_file_count / list_entries / read_entry
Sidebar sidebar: true (do not list widget or ids) setup() then register_sidebar
Display filter permissions.filter: true setup() then register_filter. Enable it in the Filter menu (not the same as plugin on/off)
Settings fields None (schema is in code) load() then register_config
Custom actions None register_action

A plugin with no formats, no sidebar, and no setup() fails to load. A filter-only plugin needs permissions.filter and setup().

Package layout

my_plugin.zip
├── manifest.json
├── src/                 # import root
│   └── plugin.py
├── langs/               # optional ja.json / en.json
├── resources/           # optional; root.read_bytes
└── LICENSE.md           # optional. Settings → License. .md then .txt then bare
  • Do not wrap the package in an extra parent folder.
  • The same layout as a folder under plugins/ loads without zipping.
  • If you have not accepted yet, a Yes / No dialog appears at startup.
  • After Yes, if more than one plugin has the same id, choose one. The choice is saved and is not asked again unless a new unresolved duplicate id appears.
  • Change it later in Plugin Settings. Unselected plugins stay in the list with a reason.
  • Root LICENSE.md / LICENSE.txt / LICENSE can be opened from the License column (that order; display is not a guarantee).

manifest.json

Place this at the ZIP or folder root. The host identifies the plugin from this file only.

id string required

Plugin id. Only one plugin with the same id is loaded at a time. Stored settings use the key id(ver:version). The ID column in Plugin Settings omits the version.

name string required

Display name shown in the plugin list.

version string required

Package version. Newer versions appear first in the duplicate-id dialog. Bumping it changes the settings key; previous values are not carried over.

api_version int required

Host contract version. Only 1 is valid today.

entry string required

module:Class. src/ is the import root. Example: plugin:FileLoader loads FileLoader from src/plugin.py. Samples and new plugins in this repo use src/plugin.py.

description string optional

Short text shown in Plugin Settings.

author string optional

Author name.

permissions object optional

Permissions the host reads from the manifest. See Manifest permissions. You cannot pass them through plugin APIs.

formats array optional

Extensions this plugin handles. The host reads them; this is the source of truth. Use [[".zip", "archive"]] or {ext, kind}. ext is a string or an array. extension / type are not read. image is one page; archive lists inner images.

{
  "formats": [[[".txt", ".log"], "archive"]]
}
sidebar bool optional

Declare that this plugin uses a sidebar. Do not list widget or sidebar ids. The widget is passed from setup() via register_sidebar. Without this flag the plugin fails to load. Plugin Settings status becomes "Failed: A registration without permission".

{
  "sidebar": true
}

Manifest permissions

manifest.json permissions is the only source. The host reads it before load. You cannot pass permissions to register_sidebar or register_filter. This is not an OS sandbox. Unknown keys are ignored. Values must be JSON true / false (the string "false" or 1 fails to load).

KeyWithout itWith it
filter register_filter fails the load. Plugin Settings status becomes "Failed: A registration without permission" The plugin may put display filters on the registry. Registering does not run process. Only ids the user enables in the Filter menu enter the pipe
inactive_callback A plugin that registered a sidebar does not get current_changed while every dock is hidden It still gets current_changed while hidden. Loader-only plugins do not need this (they already receive it) 
{
  "permissions": {
    "filter": true,
    "inactive_callback": true
  }
}

FileLoader

The host constructs the class from manifest.entry with Class(), then calls required load(root, get_text, host) and the fixed method names. Do not import ez_co.plugins.api. Sidebar-only and filter-only plugins use the same entry. Formats come from manifest.formats.

Minimal image loader (src/plugin.py)

class FileLoader:
    def __init__(self):
        self.root = None
        self.get_text = None
        self.host = None

    def load(self, root, get_text, host):
        self.root = root
        self.get_text = get_text
        self.host = host

    def get_file_count(self, file_path):
        return 1

    def list_entries(self, file_path):
        return [file_path.replace("\\", "/").split("/")[-1]]

    def read_entry(self, file_path, index):
        with open(file_path, "rb") as handle:
            data = handle.read()
        return _Entry(self.list_entries(file_path)[index], data)


class _Entry:
    def __init__(self, name, data):
        self.name = name
        self.data = data
ctorClass()

No arguments. Initialize fields that stay inside the class. Do not take root / get_text / host. register_* / on / off raise and the plugin fails to load.

def __init__(self):
    self.root = None
    self.get_text = None
    self.host = None
    self.widget = None
methodget_file_count(file_path: str) -> int

Entry count. Archives: len(list_entries(...)). Images: usually 1.

def get_file_count(self, file_path):
    return len(self.list_entries(file_path))
methodlist_entries(file_path: str) -> sequence[str]

Entry names, not directories. Order is page order. Encrypted archives need a password here or the count is 0.

def list_entries(self, file_path):
    names = []
    with ZipFile(file_path) as archive:
        for name in archive.namelist():
            if name.endswith("/"):
                continue
            if name.lower().endswith((".png", ".jpg", ".webp")):
                names.append(name)
    return names
methodread_entry(file_path: str, index: int) -> object

Return an object with name (str) and data (bytes PIL can open). May run on a worker. Use host APIs for UI.

def read_entry(self, file_path, index):
    name = self.list_entries(file_path)[index]
    with ZipFile(file_path) as archive:
        data = archive.read(name)
    return _Entry(name, data)
methodload(root, get_text, host)

Required. Called once after construct, even if the plugin is off. Keep the arguments on self. register_config is allowed here. UI registers (register_sidebar / register_action / register_filter / on / off) raise and the plugin fails to load. If load raises after a register, the host drops that plugin's ledger and config schema.

ArgMeaning
rootFiles in the plugin: read_bytes / exists
get_textStrings
hostRegister, config, state. Call methods as self.host.ask_password. Do not use getattr
 
def load(self, root, get_text, host):
    self.root = root
    self.get_text = get_text
    self.host = host
    host.register_config("strict", "bool", default=True, label="Strict")
methodsetup() / teardown()

Optional. Called on enable / disable. After teardown the host clear_plugin removes sidebars, actions, listeners, and that plugin's filter records. Pipe IDs stay. Config schemas stay. If setup raises, the host tries teardown then clear_plugin. It does not pass the failure to teardown. Do not call off / unregister_* from teardown. Teardown is only for plugin-owned things such as a QThread or timer. For a sidebar, set manifest.sidebar: true first. For a filter, set permissions.filter: true first.

def setup(self):
    widget = self.host.load_ui(self.root.read_bytes("resources/sidebar.ui"))
    self.host.register_sidebar("info", self.get_text("title"), widget)
    self.host.on("current_changed", self._on_current)

def teardown(self):
    if self._thread is not None:
        self._thread.quit()
        self._thread.wait()
        self._thread = None

methodhost.on(event, callback) / host.off(event, callback=None)

current_changed and config_changed. Omitting callback on off removes all of this plugin's handlers for that event. Disable cleanup is the host clear_plugin. Use off only while still enabled. For plugins that registered a sidebar, current_changed is delivered only while a dock is visible or permissions.inactive_callback is set. config_changed is always delivered.

def _on_current(payload):
    self._refresh(payload.get("folder"))

def _on_config(payload):
    if payload.get("key") == "fetch_web":
        self._refresh(host.get_current("folder"))

host.on("current_changed", _on_current)
host.on("config_changed", _on_config)
host.off("current_changed")

methodhost.register_filter(filter_id, title, process) -> None

Rewrites the displayed image. Requires permissions.filter: true first (you cannot pass it through the API). Without it the plugin fails to load. Plugin Settings status becomes "Failed: A registration without permission". Public id is plugin:{plugin_id}:{filter_id}. filter_id cannot contain :. Call more than once from setup() with different ids. Registering does not call process. Only ids the user enables in the Filter menu enter the pipe; the host applies them in that order. Settings use existing register_config (no filter-only config API; one dialog even with several filters). v1 process(image, context) is synchronous and for short work. context is path / page / size (no Host). The original cache object is not passed in. Plugin on/off is not the same as the filter pipe.

def _sharp(image, context):
    return image.filter(ImageFilter.SHARPEN)

host.register_filter("sharp", get_text("sharp"), _sharp)
# Public id: plugin:com.example.x:sharp

See also: unregister_filter

Plugin config

The host Plugin Settings dialog (on/off and extension handlers) is not the same as a plugin's own values. This section is the latter. Signatures are under register_config / get_config / set_config / delete_config.

Schema

  • Call host.register_config(key, value_type, default, label, description, choices=None, minimum=None, maximum=None, step=None, path_kind=None, path_filter=None, sync=False, reload=False, multiple=False, suffix=None, required=False) from load. Schema survives disable, so that is the right place. __init__ raises.
  • value_type is "bool" / "string" / "int" / "float" / "int_range" / "float_range" / "path" / "password" / "color" / "date" / "datetime" / "choice" / "font" / "charset" / "language" / "country".
  • int_range / float_range are a single number in a range. minimum / maximum / step are required. Missing values, a reversed range, or step <= 0 raise an error. The dialog shows a slider and a spin box, and appends the range to the item name. float_range also appends step.
  • path is a string. path_kind is "file" (default) or "directory". path_filter is the file-dialog filter.
  • password is masked in the dialog. Storage uses Windows DPAPI. get_config still returns plaintext to the plugin.
  • sync=True applies only to numeric types (int / float / int_range / float_range). After 500ms idle the host stores the value and emits config_changed. reload=True (with sync) also calls reload_current. Cancel (including Esc / the window close button) restores previewed values to the snapshot from when the dialog opened, or from the last Apply. reload fields also restore the image.
  • color is a #RRGGBB string. date / datetime are Unix seconds in UTC (number). date is midnight UTC of that day.
  • choice needs choices (values, (value, label) pairs, or an Enum / member list). Without it the field is a one-line edit. Passing an Enum makes get_config / config_changed return members. Storage is the canonical .name. Do not rename members if you need saved settings to round-trip. An unknown name falls back to default. For multiple, one unknown name resets the whole value to default.
  • charset / language / country lists are owned by the host. Storage is the codec name / language code / country code. Language and country labels use native names and do not follow the app UI language.
  • multiple=True stores a JSON array. [] is kept as-is (zero items are allowed). required=True (default False) rejects empty values on save. An empty default may still be registered. If the type cannot represent empty, required has no extra effect.
  • suffix is display-only to the right of numeric fields and is not stored. description is a tooltip only when set (no fallback to the label).
  • label is the row name in the settings dialog. If omitted, the key is shown.
  • Registering at least one field adds a Settings button on the plugin row. Otherwise the cell is -.

Read and write

  • get_config(key, default) returns the stored value. If none is stored, it uses the schema default, then the argument default. The value is coerced to the schema type. Enum choice returns the member; multiple=True returns a list.
  • set_config(key, value) coerces, stores, and emits config_changed ({key, value}) to this plugin only. Empty required values are not stored and return False.
  • delete_config(key) deletes the stored value. The schema stays, so the next get_config returns the default.
  • The plugin API has no plugin_id argument. The host you receive only sees this plugin's rows.
  • host.get_app_config() is a read-only snapshot of host language / viewer / cache / ui_font. It is not plugin config.

Storage

  • Values live in the current profile's plugin_settings table. They are copied when you add a profile and removed when you delete it.
  • The row key is a hash of plugin_id. Other plugins cannot read these rows.
  • Keys are short names you choose (for example fetch_web). Bumping manifest.json version does not change the row if id stays the same.
  • That is separate from id(ver:version) used in plugins.extension_handlers.
  • They are not written to the YAML export of host settings. Import / export of host config does not copy them.
  • plugin_settings.value is JSON. date / datetime / int / float / int_range / float_range are numbers; color / path / charset / language / country are strings. Enum choice stores the member name. multiple=True stores an array. password is a DPAPI token string.

Settings dialog

  • Settings on the plugin row opens a small dialog with only the registered fields.
  • OK / Apply on that dialog writes to the database immediately. It does not wait for OK on the host Plugin Settings dialog.
  • Reset restores widgets to the schema default. Non-sync fields are not stored yet. Numeric sync fields are stored immediately. reload=True also reopens the image.
  • Cancel drops unsaved edits. It also restores any sync preview writes to the snapshot from when the dialog opened, or from the last Apply. reload fields also reopen the image. Esc and the window close button do the same.
  • Listen for config_changed and update the sidebar or other UI. The host reopens the source only for reload=True; do not also call reload_current for those.
def load(self, root, get_text, host):
    self.host = host
    host.register_config(
        "fetch_web",
        "bool",
        default=True,
        label=get_text("config.fetch_web"),
        description=get_text("config.fetch_web.desc"),
    )
    host.on("config_changed", self._on_config)

def _on_config(self, payload):
    if payload.get("key") == "fetch_web":
        self._apply(payload.get("value"))

# later
if host.get_config("fetch_web"):
    self._fetch(host.get_current("folder"))

Events

current_changed

Fired when the current file changes. Payload is {path, folder, page}. Plugins that registered a sidebar receive it only while a dock is visible or permissions.inactive_callback is set.

config_changed

Fired after this plugin's set_config. Payload is {key, value}. Other plugins' changes are not delivered.

def _on_current(payload):
    print(payload["folder"], payload["page"])

def _on_config(payload):
    print(payload["key"], payload["value"])

host.on("current_changed", _on_current)
host.on("config_changed", _on_config)

Limits

  • No import ez_co and no imports from other plugins
  • Dock placement / floating is host-owned
  • Other plugins' settings are not readable (plugin_id is hashed)
  • DLL plugins are not supported
  • Restart after adding or removing a ZIP or folder. On/off, handler choice, and changing a duplicate-id source apply on OK / Apply
  • If not accepted, Yes / No. No skips loading and hides Plugin Settings. Consent is per user. The question returns next start and when the consent version is raised
  • If more than one plugin has the same id, choose one after consent. The choice is saved; change it later in Plugin Settings (OK / Apply; no restart)
