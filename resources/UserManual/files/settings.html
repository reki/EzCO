⚙️ 設定

EzCoの設定はSQLiteデータベース（config.db）に、プロファイル単位で保存されます。設定ダイアログからの変更は現在のプロファイルに反映されます。このページでは各項目の意味と内部キー名を説明します。YAML例はエクスポート形式の参考です。

データの置き場（config.db と plugins など）だけはプロファイル共通です。初回起動で選び、あとから全般タブで変えられます。変更は次回起動時に反映されます。

⚠️ 重要な注意

  • 通常は設定ダイアログから変更してください。変更は現在のプロファイルに保存されます
  • YAMLを直接扱う場合は、エクスポートしたファイルを編集してインポートしてください。インポートは現在のプロファイルを上書きします
  • YAML形式ではインデント（字下げ）が重要です。スペースを使用し、タブは使わないでください
  • 旧バージョンのconfig.yamlが残っている場合、起動時に取り込み確認が表示されます

📂 データの置き場（プロファイル共通）

場所の設定は、このユーザーのデータフォルダにある user.json に保存します。UI には技術的なフォルダ名は出しません。

このユーザーのデータフォルダ（推奨） data_location=user 選択

この Windows ユーザー専用のフォルダに config.db と plugins を置きます。初回に場所の設定が無いときは、起動ダイアログでも選べます。

実行ファイルと同じフォルダ data_location=exe 選択

実行フォルダに設定を置きます。同じ PC の他のユーザーも、その設定を読んだり変えたりできることがあります。

フォルダを指定 data_location=custom 選択

任意のフォルダを使います。他のユーザーが読める場所だと、設定を共有してしまうことがあります。

🪟 ウィンドウ設定 (window)

ウィンドウの表示に関する設定を行います。

幅 window.width 整数

ウィンドウの初期幅をピクセル単位で指定します。

デフォルト: 800（推奨: 800～1920）
高さ window.height 整数

ウィンドウの初期高さをピクセル単位で指定します。

デフォルト: 600（推奨: 600～1080）
自動リサイズ window.auto_resize 真偽値

画像を読み込んだ時に、ウィンドウサイズを画像に合わせて自動調整します。

デフォルト: false
常に手前表示 window.always_on_top 真偽値

ウィンドウを常に最前面に表示します。

デフォルト: false
ウィンドウ状態保存 window.save_window_state 真偽値

ウィンドウのサイズ・位置・最大化（フルスクリーンではない）を終了時に保存し、次回起動時に復元します。ファイルを開いていなくても保存します。最大化中でも、元の通常サイズを別途覚えておきます。

デフォルト: true
最大化状態 window.maximized 真偽値

終了時にウィンドウが最大化されていたかです。設定画面には出ず、自動保存されます。フルスクリーンとは別です。

デフォルト: false
起動時は常に最大化 window.maximize_on_startup 真偽値

前回が通常サイズでも、起動時は常にウィンドウを最大化します。

デフォルト: false
サイドバー状態 window.dock_state 文字列

開いていたサイドバー、左右の位置、幅を保存します。プロファイル単位で、次回起動時とプロファイル切替時に復元します。この項目は自動保存され、設定画面には出ません。

window: width: 1024 # ウィンドウの幅（ピクセル） height: 768 # ウィンドウの高さ（ピクセル） auto_resize: true # 画像に合わせてウィンドウサイズを自動調整 always_on_top: false # 常に最前面に表示 save_window_state: true # ウィンドウ状態を保存・復元 maximized: false # 終了時に最大化していたか（自動保存） maximize_on_startup: false # 起動時は常に最大化 min_width: 400 # 最小幅（ピクセル） min_height: 300 # 最小高さ（ピクセル） x: 100 # 初期X座標 y: 100 # 初期Y座標

🖼️ ビューア設定 (viewer)

画像の表示に関する設定を行います。

背景色 viewer.background_color 文字列

ビューアの背景色を16進カラーコードで指定します。

デフォルト: "#c0ffc0" (薄緑色)
色の例:
"#000000" (黒)
"#ffffff" (白)
"#2b2b2b" (ダークグレー)
"#f0f0f0" (ライトグレー)
ウィンドウに合わせる viewer.fit_to_window 真偽値

画像をウィンドウサイズに合わせて自動的に拡大・縮小します。

デフォルト: false
最小縮小率制限 viewer.fit_to_window_minimum 真偽値

最小縮小率を100%（等倍）までに制限します。

デフォルト: true
ページ表示モード viewer.page_mode 文字列

単ページまたは両開きの並びを指定します。メニューバーの表示からも切り替えできます。表示画像の明るさなどはメニューバーのフィルターです。

デフォルト: "single"（single / spread_right / spread_left）
選択ページを軸 viewer.spread_selected_as_axis 真偽値

両開き時、スライダーで選んだページを見開きの先頭（N）にし、隣を N+1 にします。

デフォルト: false
両開き／単ページ切替の優先 viewer.spread_toggle_preference 文字列

両開き切替アクションや単ページとの行き来で、どちらの見開きを使うかを決めます。

デフォルト: "keep_previous"（keep_previous / prefer_right / prefer_left）
画像移動感度 viewer.image_move_sensitivity 小数

画像をドラッグで移動する際の感度を設定します（0.5～2.0）。

デフォルト: 1.2
viewer: background_color: "#2b2b2b" # ビューアの背景色（16進カラーコード） fit_to_window: true # 画像をウィンドウサイズに自動調整 fit_to_window_minimum: true # 最小縮小率を100%に制限 page_mode: "spread_right" # single / spread_right / spread_left spread_selected_as_axis: false # スライダー選択ページを見開きの軸にする spread_toggle_preference: "keep_previous" # keep_previous / prefer_right / prefer_left mouse_lock: false # マウスロック機能 mouse_lock_hide_cursor: true # マウスロック時にカーソルを非表示 image_move_sensitivity: 1.5 # 画像移動感度（0.5～2.0）

💾 キャッシュ設定 (cache)

画像のキャッシュとプリフェッチに関する設定を行います。これらの設定により、ページめくりの応答性を大幅に改善できます。

メモリキャッシュサイズ cache.memory_limit 文字列

読み込んだ画像をメモリに保持するキャッシュのサイズを文字列形式で指定します。大きく設定するほど、より多くの画像をメモリに保持でき、ページめくりが高速になります。

デフォルト: "256MB"（推奨: "128MB"～"8GB"）
設定例:
• 低スペックPC: "128MB"～"256MB"
• 標準PC: "512MB"～"1GB"
• 高スペックPC: "2GB"～"8GB"
• 数値形式: "1.5GB", "2.5GB"なども可能
プリフェッチページ数 cache.prefetch_pages 整数

現在のページから前後何ページ分を先読みしてキャッシュするかを設定します。大きく設定するほど、より多くのページが事前に読み込まれ、スムーズなページめくりが可能になります。

デフォルト: 15（推奨: 5～30、範囲: 1～50）
最適化のポイント:
• 高速SSD環境: 10～15ページ（読み込み速度が速いため）
• HDD環境: 20～30ページ（読み込み速度が遅いため多めに設定）
• 大容量ファイル: 5～10ページ（メモリ使用量を抑制）
• 小容量ファイル: 25～50ページ（より多くのページを先読み）

💡 キャッシュの動作仕様

  • 距離ベース削除: メモリ上限に達すると、現在のページから最も遠いページから削除
  • プリフェッチ優先度: 現在のページ → 次のページ → 前のページ → 前後2-3ページの順
  • バックグラウンド処理: 別スレッドで実行されるため、メイン表示に影響なし
  • 適応制御: ファイルハンドル非保持モード時は一部制限される場合あり
cache: memory_limit: "512MB" # キャッシュメモリサイズ（文字列形式） prefetch_pages: 15 # 事前読み込みページ数（1～50）

📚 履歴設定 (history)

ファイル閲覧履歴に関する設定を行います。

最大保存数 history.max_count 整数

履歴として保存する項目の最大数を指定します（1～99）。

デフォルト: 20（範囲: 1～99）
ページ復元 history.restore_page_on_reopen 真偽値

同じファイルやフォルダを再度開く際に、履歴に保存された最後のページを自動的に復元します。

デフォルト: false
💡 機能説明:
• 以前開いたファイルのページ位置を記憶
• フォルダやアーカイブファイルにも対応
• 無効の場合は常に1ページ目から開始
起動時復元 history.open_last_file_on_startup 真偽値

アプリケーション起動時にコマンドライン引数でファイルが指定されていない場合、自動的に最後に開いたファイルを開きます。

デフォルト: false
💡 機能説明:
• 前回終了時に開いていたファイルを自動で再開
• コマンドライン引数でファイルが指定された場合は無効
• 履歴が空の場合は何も開かない
history: max_count: 50 # 履歴の最大保存数（1～99） restore_page_on_reopen: true # 同じファイルを開く際にページを復元 open_last_file_on_startup: true # 起動時に最後に開いたファイルを開く

🌐 言語設定 (language)

表示言語に関する設定を行います。

言語コード language.code 文字列

表示言語を指定します。

デフォルト: "system"
指定可能な値: "system", "ja", "en"
言語コードの説明:
• "system": OSの言語設定に従う
• "ja": 日本語
• "en": 英語
• カスタム言語: langs/フォルダに独自言語ファイルを追加可能
language: code: "ja" # 表示言語（"system", "ja", "en", または外部言語ファイル名）

🐛 デバッグ設定 (debug)

デバッグ機能とファイルハンドル管理に関する設定を行います。

デバッグモード debug.enabled 真偽値

デバッグモードを有効にすると、次回起動時にlogsフォルダにログファイルが作成されます。

デフォルト: false
ファイル／フォルダハンドルを保持 debug.keep_archive_handles 真偽値

アーカイブファイルやフォルダを開く際のファイルハンドル管理方法を設定します。この設定により、ファイルロックの発生を制御できます。

デフォルト: false（推奨: 無効）
⚠️ 重要な注意:
• 無効（推奨）: ファイルロックが発生せず、フォルダやファイルの移動・削除が可能
• 有効: 高速なファイルアクセスだが、ファイルロックが発生し移動・削除不可
• 対象形式: ZIP、TAR、圧縮ファイル、フォルダスキャン
• 非対象: 7Z、RAR（専用ライブラリのため常に適切な管理）
ファイルメタデータキャッシュ debug.cache_archive_metadata 真偽値

アーカイブファイルの構造情報をメモリにキャッシュして高速化します。（将来の機能拡張用）

デフォルト: true
エラー時にエラーログを表示する debug.show_error_log 真偽値

プラグインの setup／コールバック／読み込み失敗と、本体の未処理例外でスタックトレースを表示し、コピーできます。通常はオフです。

デフォルト: false

🔧 ファイルハンドル管理の使い分け

  • コミック整理作業中: keep_archive_handles: false（ファイル移動・リネーム・削除を頻繁に行うため）
  • 読書専用環境: keep_archive_handles: true（ファイル操作は行わず、読み込み速度を最優先）
  • ネットワークドライブ使用: keep_archive_handles: true（ネットワーク遅延を最小化）
debug: enabled: true # デバッグログを有効にする keep_archive_handles: false # ファイルハンドル保持（推奨: false） cache_archive_metadata: true # アーカイブメタデータキャッシュ show_error_log: false # エラー時にスタックトレースを表示する

📦 アーカイブ設定 (archive)

互換用の内部キーです。画面からの操作はメニューの「プラグイン設定」で、拡張子の読み込み方式を「読み込まない」にします。プラグイン設定を保存すると、こちらのキーも同期されます。

アーカイブサポート archive.enabled 真偽値

アーカイブファイル全体のサポートを有効/無効にします。無効にすると個別設定は無視されます。

デフォルト: true

📋 対応アーカイブ形式

以下の各形式について、個別に有効/無効を設定できます：

  • ZIP (.zip) - 最も一般的な圧縮形式 (設定キー: zip)
  • 7-Zip (.7z) - 高圧縮率の形式 (設定キー: 7z)
  • RAR (.rar) - WinRAR形式 (設定キー: rar)
  • TAR (.tar) - Unix系の書庫形式 (設定キー: tar)
  • TAR.GZ (.tar.gz, .tgz) - 設定キー: tar_gz
  • TAR.BZ2 (.tar.bz2, .tbz2) - 設定キー: tar_bz2
  • TAR.XZ (.tar.xz, .txz) - 設定キー: tar_xz
  • CBZ/CBR (.cbz, .cbr) - コミック専用形式 (設定キー: cbz, cbr)
  • PDF (.pdf) - ページをそのまま表示。描画できない場合は埋め込み画像 (設定キー: pdf)。パスワード付きPDFは入力ダイアログで解除し、履歴に暗号化して保存します
  • GZ/BZ2/XZ (.gz, .bz2, .xz) - 単一ファイル圧縮 (設定キー: gz, bz2, xz)
archive: enabled: true # アーカイブサポート全体の有効/無効 zip: true # ZIP形式（.zip） 7z: true # 7-Zip形式（.7z） rar: true # RAR形式（.rar） tar: true # TAR形式（.tar） tar_gz: true # TAR.GZ形式（.tar.gz, .tgz） tar_bz2: true # TAR.BZ2形式（.tar.bz2, .tbz2） tar_xz: true # TAR.XZ形式（.tar.xz, .txz） gz: false # GZ形式（通常は画像圧縮に使わない） bz2: false # BZ2形式（通常は画像圧縮に使わない） xz: false # XZ形式（通常は画像圧縮に使わない） cbz: true # コミックブック ZIP（.cbz） cbr: true # コミックブック RAR（.cbr） pdf: true # PDF（.pdf）

🔤 UIフォント設定 (ui_font)

アプリケーションのUI要素に使用するフォントを設定します。

フォントファミリ ui_font.font_family 文字列

UIで使用するフォント名を指定します。システムにインストールされているフォントを使用してください。

デフォルト: システム依存
日本語候補: "メイリオ", "游ゴシック", "ＭＳ ゴシック"
英語候補: "Segoe UI", "Arial", "Tahoma"
💡 フォント追加方法:
• font/フォルダにTTFファイルを配置
• システムフォントとカスタムフォントの両方が利用可能
フォントサイズ ui_font.font_size 整数

UIフォントのサイズをポイント単位で指定します。

デフォルト: 10 (推奨範囲: 8～16)
文字色 ui_font.font_color 文字列

UI文字の色を16進カラーコードで指定します。

デフォルト: "#00008d" (濃い青)
文字色の例:
"#000000" (黒)
"#333333" (ダークグレー)
"#ffffff" (白)
"#0066cc" (青)
"#008000" (緑)
背景色 ui_font.bg_color 文字列

UI要素の背景色を16進カラーコードで指定します。

デフォルト: "#ffffff" (白)
背景色の例:
"#ffffff" (白)
"#f0f0f0" (薄いグレー)
"#2b2b2b" (ダークグレー)
"#000000" (黒)
"#fffacd" (薄い黄色)
透明度 ui_font.alpha 整数

UI要素の透明度を0（完全透明）～255（完全不透明）で指定します。

デフォルト: 150 (約60%の不透明度)
ui_font: font_family: "メイリオ" # UIフォント名（システム or fontフォルダ） font_size: 12 # フォントサイズ（ポイント） font_color: "#000000" # 文字色（16進カラーコード） bg_color: "#ffffff" # 背景色（16進カラーコード） alpha: 200 # 透明度（0～255）

🖼️ 画像一覧設定 (image_list)

画像一覧ダイアログの動作を設定します。

選択後に閉じる image_list.close_after_select 真偽値

画像を選択した後に自動的にダイアログを閉じるかどうかを設定します。

デフォルト: true
image_list: close_after_select: false # 選択後にダイアログを閉じる（true）/開いたまま（false）

🗂️ タブ設定 (viewer.drop_opens_new_tab)

ファイルをドロップしたときの開き先です。

  • メニューの「ファイルを開く」は今のタブ、「新しいタブでファイルを開く」は新規タブです。
  • 履歴とブックマークは、クリック＝今のタブ、Ctrl+クリックまたは中央クリック＝新しいタブです。右クリックでも選べます。
  • タブバーの中央クリックは、そのタブを閉じます。
ファイルのドロップ先 viewer.drop_opens_new_tab 真偽値

false なら既存タブ、true なら新しいタブ。先頭グループのあと、別タブ指定のアーカイブ／フォルダなどは追加タブになります。最後のタブを閉じるとウィンドウも閉じます。

デフォルト: false
アーカイブは別タブで開く viewer.open_archives_in_own_tab 真偽値

true ならアーカイブは1ファイル1タブ。false なら画像などと同じタブのページ列に含めます。種別はプラグイン設定に従います。

デフォルト: true
フォルダは別タブで開く viewer.open_folders_in_own_tab 真偽値

true ならフォルダは1つ1タブ。false なら画像などと同じタブのページ列に含めます。

デフォルト: false
フルスクリーン時にタブを表示 viewer.show_tabs_in_fullscreen 真偽値

表示メニューのチェックで切り替えます。false ならフルスクリーン中はタブバーを隠します。タブが 1 枚だけのときは、通常時もタブバーは出ません。

デフォルト: false
フルスクリーン時にページスライダーを表示 viewer.show_page_slider_in_fullscreen 真偽値

表示メニューのチェックで切り替えます。false ならフルスクリーン中は他のドックと同じくページスライダーを隠します。true なら出したまま残します。フルスクリーン中はマウスが中央に固定されるため、スライダーは操作できません。

デフォルト: false

タブバーの幅は固定です。長い名前は省略し、マウスを乗せると全文が出ます。ショートカット設定にあるキーボード割り当ては、対応するメニュー項目の右側に表示されます。

🔌 プラグイン設定 (plugins)

メニューの「プラグイン設定」で、プラグインの ON/OFF、拡張子ごとの読み込み方式、読み込み済みの一覧を扱います。表示画像への加工はメニューバーの「フィルター」で、プラグイン ON とは別に有効／無効にできます。

ZIP または manifest.json 付きフォルダは、データの置き場（設定の「データの置き場」）にある plugins/ 直下に置きます。

導入と再起動

  • プラグインがあるのに未同意のときは、起動時にはい／いいえの確認が出ます。
  • はいなら、このユーザーの user.json に同意バージョンを保存します。重複があれば、その次に選択ダイアログを出します。
  • いいえなら、その起動ではロードせず、このメニュー項目も出しません。次回起動でもまた聞きます。
  • 同意の文面を変えてバージョンが上がったときも、再表示します。
  • 新しい ZIP／フォルダを置いた（または消した）あとは、再起動が必要です。
  • ON/OFF、読み込み方式、重複の選び直しは、OK / 適用で足り、再起動は不要です。

一覧とライセンス

  • 同じ id が複数あるときは、同意したあとの起動時に1つ選びます。選ばれなかったものは、一覧に理由付きで残ります。
  • OFF にしたプラグインは、無いものとして扱います。
  • ルートに LICENSE.md / LICENSE.txt / LICENSE があれば、ライセンス列から読めます（優先順はこの順。表示は保証ではありません）。
  • プラグインが項目を登録していれば、設定列からそのプラグイン専用の値を変えられます。保存のしかたは プラグインリファレンス です。

注意

  • 本体はプラグインの中身を検査しません。置いたコードはアプリと同じ権限で動きます。
  • 悪意のあるコードや欠陥による損害について、EzCo の開発者は責任を負いません。責任は配布者と、それを導入した使用者にあります。
  • ON/OFF と読み込み方式は、現在のプロファイルに保存されます。
  • 旧アーカイブ設定の代替として、読み込み方式に「読み込まない」があります。
  • 有効なプラグインの拡張子は、「ファイルを開く」の「対応しているファイル」と「プラグイン形式」に入り、フォルダを開いたときのスキャン対象にも含まれます。
  • 商品情報サイドバーは product_info プラグインです。ホスト API は プラグインリファレンス を見てください。
導入の同意 plugin_consent_version 文字列

プロファイルではなく、このユーザーの user.json に保存します。はいを選んだときの同意バージョンです。値の元は src/ez_co/resources/plugin_consent/version.txt（例 1.0.0）です。無い・不正・ファイルと不一致のときは未同意です。いいえでは書きません。本文を変えたら version.txt を上げます。未同意のときはプラグインをロードせず、この設定画面もメニューに出しません。

デフォルト: 無し（未同意）
プラグインの有効／無効 plugins.enabled オブジェクト

プラグイン ID ごとの ON/OFF です。未記載は有効です。OFF にすると拡張子の担当から外れ、サイドバーも消えます。

デフォルト: 空（すべて有効）
拡張子ごとの読み込み方式 plugins.extension_handlers オブジェクト

拡張子から builtin、id(ver:version)、または none（読み込まない）への対応です。OK / 適用で開いているファイルを再読み込みします（再起動は不要）。ページ数が足りなければ末尾のページに寄せます。

デフォルト: 空（ビルドインが知っている拡張子はビルドイン優先）
重複プラグインの選択 plugins.source_choice オブジェクト

同じ id が複数あるときの選択です。値は source（plugins/ 直下の名前、または none）です。一度選んだ id は、選んだファイルが残っている限り起動時に再表示しません。新しい重複 id が出たとき、または選んだファイルが消えたときだけ聞きます。選び直すときはプラグイン設定の「重複プラグインの選択」です。反映は設定の OK / 適用と同じです。

ダイアログの列レイアウト plugins.dialog オブジェクト

一覧の列幅と列順です。ヘッダーをドラッグして変更できます。はみ出した分は横スクロールします。OK / キャンセルどちらでも保存します。ID 列はバージョンなしのプラグイン ID です。

👤 プロファイル

プロファイルごとに設定・ブックマーク・履歴が分かれます。現行プロファイルはconfig.dbのapp_state.current_profileに保存されます。

📋 プロファイルの概念

  • 独立データ: 各プロファイルは独自の設定・ブックマーク・履歴を持ちます
  • 用途分け: 仕事用、プライベート用、研究用など目的別に管理
  • メニュー操作: メニューバーのプロファイルから追加・管理（改名・削除）・選択
  • 追加時は現在の設定をコピー: 表示・ショートカット・プラグイン優先度など。履歴とブックマークはコピーせず空です
  • 既定は削除不可: 初回作成される既定プロファイルは削除できません

⚠️ プロファイル使用時の注意点

  • 完全分離: 表示モード、背景、言語、ショートカット、プラグイン選択、ブックマーク、履歴はプロファイルごとに分かれます
  • 削除注意: プロファイルを削除すると、その設定・ブックマーク・履歴は完全に削除されます
  • CLIはセッション限定: --profile=名前 / -p 名前はその起動中だけ使います。前回の選択は書き換えません
  • 存在しない名前: CLIで無いプロファイルを指定しても作成せず、前回のプロファイルを使います
  • エクスポート/インポート: 現在のプロファイルの設定をYAMLで書き出し／上書きします

プロファイルの作成と切り替え方法

📋 メニューから

プロファイル → 追加、管理、一覧から選択。追加すると今の設定をコピーします（履歴・ブックマークは空）。切替はすぐに反映されます。

🚀 起動時指定

EzCo.exe --profile=プロファイル名でそのセッションだけ指定できます。存在しない場合は作成せず、前回のプロファイルを使用します。

📥 旧YAMLの取り込み

残っているconfig.yamlは起動時の確認後、選んだプロファイルへ取り込めます。

プロファイル使用例

用途 プロファイル名例 説明
仕事用 "仕事", "Work", "業務" 業務関連の資料やマニュアルの閲覧
趣味・娯楽 "プライベート", "漫画", "エンタメ" 個人的な画像や漫画の閲覧
学習・研究 "研究", "勉強", "参考資料" 学術資料や技術文書の閲覧
プロジェクト別 "プロジェクトA", "案件X" 特定プロジェクトの資料管理
🎯 プロファイル活用のコツ:
• 目的別分類: 仕事、プライベート、学習など明確に用途を分ける
• 一時プロファイル: 特定の作業用に一時的なプロファイルを作成
• 起動スクリプト: バッチファイルで既存プロファイルを指定して起動を自動化
• 定期整理: 不要になったプロファイルは定期的に削除して管理
